# 积分设计

## 目标

- 0 通关时，只能开少量基础加成。
- 想要威望、额外升级、强通用加成，必须带因子。
- 随着地图逐步通关，可开的配置越来越多。
- 全图通关后，可以稳定高配。
- 即使全图通关，想满配也仍然要选几个因子。

## 双资源模型

使用两类资源：

- `通关点`
  来源是地图首通、奖励任务首通、指挥官首通。
  作用是代表长期进度。
- `因子点`
  主要来源是本局选择的因子。
  作用是代表这局额外承担的难度。

核心原则：

- 纯长期进度不能直接白嫖所有强配置。
- 纯因子也不能替代长期通关积累。
- 强项目同时消耗两类资源，这样就能稳定逼出“通关 + 因子”双要求。

## 预算公式

启动前同时校验两条：

- `通关点收入 - 通关点消耗 >= 0`
- `因子点收入 - 因子点消耗 >= 0`

只要任意一条小于 0，就不允许启动。

## 资源来源

### 通关点

- 地图首次通关：`+10`
- 地图首次完成奖励任务：`+10`
- 指挥官首次通关：`+2`

### 因子点

- 普通因子：`+1`
- 中等因子：`+2`
- 高难因子：`+4`
- 随机 / 轮换随机：`+0`

这样设计的原因很简单：

- 通关点负责“长期解锁”
- 因子点负责“本局资格”

## 消耗规则

## 通用加成

### 低档基础项

这类只消耗通关点，不消耗因子点。

- `CreepRegeneration`：`通关点 -1`
- `MechanicalRepair`：`通关点 -1`
- `MaxSupply50`：`通关点 -2`

用途：

- 给 0 通关或低进度玩家一点可选空间。
- 保证不带因子时也不是完全不能开。

### 中档强化项

这类同时消耗两类资源。

- `GuardianShell`：`通关点 -2`，`因子点 -1`
- `ChronoBoost`：`通关点 -2`，`因子点 -1`
- `RichResources`：`通关点 -3`，`因子点 -1`

用途：

- 一旦开始碰明显改变战斗或经济节奏的加成，就必须带因子。

### 高档强力项

这类强制双消耗，而且因子点消耗更高。

- `ZeroSupply`：`通关点 -4`，`因子点 -3`

用途：

- 这是最容易破坏平衡的全局项，必须卡因子。

### 分级资源项

- `DoubleMinerals`：`每级 通关点 -1，因子点 -1`
- `DoubleVespene`：`每级 通关点 -1，因子点 -1`

用途：

- 资源倍率是最稳定的滚雪球项。
- 只要开倍率，就必须带因子。
- 多级倍率天然会把因子需求越推越高。

## 威望

威望统一双消耗：

- 第 1 个威望：`通关点 -2`，`因子点 -1`
- 第 2 个威望：`通关点 -3`，`因子点 -2`
- 第 3 个威望：`通关点 -4`，`因子点 -3`

这样做的结果：

- 单威望可以较早解锁。
- 双威望开始明显要求因子支撑。
- 三威望一定要带足够因子，不可能靠老存档白开。

## 额外升级

额外升级也统一双消耗。

建议分两档：

- 常规额外升级：`通关点 -3`，`因子点 -1`
- 强力额外升级：`通关点 -4`，`因子点 -2`

如果前期不想分档，可以先统一：

- 所有额外升级：`通关点 -3`，`因子点 -1`

这样做的结果：

- 额外升级不会只靠通关点堆满。
- 想多挂升级，必须主动提高本局难度。

## 目标手感

### 0 通关

- 不带因子时，只能开 `菌毯回血`、`机械维修`、`人口+50` 这类低档基础项。
- 只要碰威望、额外升级、资源倍率、0人口，就会卡因子点。

### 中期

- 打过一些图后，通关点开始充裕。
- 但想开中档强化和 1 到 2 个威望，仍然要带 1 到 3 个因子。

### 全通后

- 通关点足够支撑高配主体。
- 但想满威望、满额外升级、双资源倍率、0人口同开，仍然会被因子点卡住。
- 这样就能保证“全通后仍然需要选几个因子”。

## 参考测算

### 轻度配置

- `CreepRegeneration`：`通关点 -1`
- `MechanicalRepair`：`通关点 -1`
- `MaxSupply50`：`通关点 -2`

合计：

- `通关点 -4`
- `因子点 0`

结论：

- 新号或低进度也能开一点基础舒适项。

### 中度配置

- `DoubleMinerals 2级`：`通关点 -2`，`因子点 -2`
- `DoubleVespene 2级`：`通关点 -2`，`因子点 -2`
- `GuardianShell`：`通关点 -2`，`因子点 -1`
- `1个威望`：`通关点 -2`，`因子点 -1`

合计：

- `通关点 -8`
- `因子点 -6`

结论：

- 就算通关点够，也至少要带 `2` 个高难因子或若干中低因子。

### 满配倾向

- `DoubleMinerals 3级`：`通关点 -3`，`因子点 -3`
- `DoubleVespene 3级`：`通关点 -3`，`因子点 -3`
- `RichResources`：`通关点 -3`，`因子点 -1`
- `GuardianShell`：`通关点 -2`，`因子点 -1`
- `ChronoBoost`：`通关点 -2`，`因子点 -1`
- `ZeroSupply`：`通关点 -4`，`因子点 -3`
- `3个威望`：`通关点 -9`，`因子点 -6`
- `2个额外升级`：`通关点 -6`，`因子点 -2`

合计：

- `通关点 -32`
- `因子点 -20`

结论：

- 通关点方面，全通后完全付得起。
- 因子点方面，仍然需要：
  - `5` 个高难因子，或
  - `3` 个高难 + `4` 个中等，或
  - 更多中低因子组合

这正好满足“全通后仍然必须选几个因子才能满配”。

## 建议落地顺序

第一版先这样做最稳：

- 先把当前单积分系统改成双字段：
  - `clearPoints`
  - `mutatorPoints`
- 通用低档项只扣 `clearPoints`
- 威望、额外升级、资源倍率、0人口改成双消耗
- WebUI 同时显示：
  - 通关点余额
  - 因子点余额
  - 当前配置双消耗

## 当前状态

- 当前文档是建议口径。
- 当前启动器还是单积分模型。
- 如果按这个方案实现，后面会比单积分更稳，也更容易逼出因子选择。
