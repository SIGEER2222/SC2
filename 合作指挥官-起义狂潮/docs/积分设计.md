# 积分设计

## 目标

- 0 通关时，只能开少量精通。
- 想开威望和额外加成，必须先解锁，再带因子。
- 随着地图逐步通关，军费越来越多，可开的精通和配置越来越多。
- 即使全图通关，想高配或满配，也仍然要选几个因子来补宝石。

## 双资源

- `军费`
  - 代表长期通关积累。
  - 主要用于精通。
  - 也用于支付威望和额外加成的一部分成本。
- `宝石`
  - 代表本局主动提高难度换来的资格。
  - 主要用于威望和额外加成。

## 预算公式

启动前同时校验：

- `军费收入 - 军费消耗 >= 0`
- `宝石收入 - 宝石消耗 >= 0`

任意一项小于 0，都不允许启动。

## 收入

### 军费

- 地图首次通关：`+10`
- 地图奖励任务 / 成就首次达成：`+10`
- 指挥官首次通关：`+2`
- 特殊挑战完成：`+10` 到 `+20`

### 宝石

宝石不靠通关给，主要靠因子给。

按因子难度给军费和宝石：

- 普通因子：`军费 +1`，`宝石 +1`
- 中等因子：`军费 +2`，`宝石 +2`
- 高难因子：`军费 +4`，`宝石 +4`
- 随机 / 轮换随机：`+0`

## 解锁规则

### 精通

- 默认可用。
- 只需要军费，不需要额外解锁。

### 威望

- 默认不建议全开。
- 通过特殊挑战逐步解锁威望槽位，或解锁具体威望。
- 解锁后，选择时仍然要消耗军费和宝石。

### 额外加成

- 默认只开放少量基础项，或全部锁定。
- 通过特殊挑战解锁对应额外加成。
- 解锁后，选择时仍然要消耗军费和宝石。

### 额外升级

- 默认锁定。
- 通过特殊挑战解锁对应额外升级。
- 解锁后，选择时仍然要消耗军费和宝石。

## 消耗规则

## 精通

- 精通只花费军费，不花费宝石。
- 建议：`每 1 点精通 = 军费 -1`

作用：

- 新号也能开少量基础数值。
- 通关越多，精通越能放开。
- 但精通本身不会逼玩家选因子。

## 威望

- 威望同时花费军费和宝石。

建议：

- 第 1 个威望：`军费 -2`，`宝石 -1`
- 第 2 个威望：`军费 -3`，`宝石 -2`
- 第 3 个威望：`军费 -4`，`宝石 -3`

作用：

- 单威望可以较早解锁。
- 双威望开始明显要求因子。
- 三威望必须带足够因子。
- 而且前提是对应威望已经被特殊挑战解锁。

## 额外加成

额外加成统一同时花费军费和宝石。

### 资源倍率

- `DoubleMinerals`：`每级 军费 -1，宝石 -1`
- `DoubleVespene`：`每级 军费 -1，宝石 -1`

### 一般额外加成

- `CreepRegeneration`：`军费 -1`，`宝石 -1`
- `MechanicalRepair`：`军费 -1`，`宝石 -1`
- `MaxSupply50`：`军费 -2`，`宝石 -1`
- `GuardianShell`：`军费 -2`，`宝石 -1`
- `ChronoBoost`：`军费 -2`，`宝石 -1`
- `RichResources`：`军费 -3`，`宝石 -1`

### 强力额外加成

- `ZeroSupply`：`军费 -4`，`宝石 -3`

作用：

- 额外加成不再能只靠通关点白开。
- 只要开始堆强加成，就一定会缺宝石。
- 这样就能稳定逼出因子选择。
- 同时还能用特殊挑战控制它们的开放顺序。

## 目标手感

### 0 通关

- 不带因子时，只能开很少量精通。
- 威望和额外加成基本都开不了，因为既没宝石，也没解锁。

### 前中期

- 通关后军费逐步变多，精通会先松开。
- 做完部分特殊挑战后，才开始逐步拿到威望、额外加成、额外升级的使用资格。
- 真正想用这些项目时，仍然要带因子补宝石。

### 全通后

- 军费足够支撑大量精通和大部分配置。
- 但只要想高威望、多额外加成、资源倍率、0人口一起上，还是会被宝石卡住。

## 参考测算

### 轻度配置

- 精通 6 点：`军费 -6`

合计：

- `军费 -6`
- `宝石 0`

结论：

- 新号不带因子，也能开一点基础精通。
- 但还碰不到威望、额外加成、额外升级的主体系。

### 中度配置

- 精通 12 点：`军费 -12`
- `DoubleMinerals 2级`：`军费 -2`，`宝石 -2`
- `1个威望`：`军费 -2`，`宝石 -1`

合计：

- `军费 -16`
- `宝石 -3`

结论：

- 军费主要靠通关积累。
- 宝石必须靠因子补。
- 同时默认要求这两个项目已经被特殊挑战解锁。

### 高配配置

- 精通 18 点：`军费 -18`
- `DoubleMinerals 3级`：`军费 -3`，`宝石 -3`
- `DoubleVespene 3级`：`军费 -3`，`宝石 -3`
- `RichResources`：`军费 -3`，`宝石 -1`
- `GuardianShell`：`军费 -2`，`宝石 -1`
- `ChronoBoost`：`军费 -2`，`宝石 -1`
- `ZeroSupply`：`军费 -4`，`宝石 -3`
- `3个威望`：`军费 -9`，`宝石 -6`

合计：

- `军费 -44`
- `宝石 -18`

结论：

- 全通后军费付得起。
- 但宝石仍然要求：
  - `4` 到 `5` 个高难因子，或
  - 若干中高难因子组合

这能保证全通后也必须带因子。

## 数据结构

### 存档统计

建议在银行里拆成这几类：

- `MapClear/<mapId>=1`
  - 地图首通
- `ObjectiveClear/<mapId>:<objectiveId>=1`
  - 奖励任务 / 成就首次达成
- `CommanderClear/<commander>:<mapId>=1`
  - 指挥官首通
- `SpecialChallenge/<challengeId>=1`
  - 特殊挑战完成

### 解锁表

建议新增三类解锁：

- `UnlockedPrestige/<commander>:<prestigeId>=1`
- `UnlockedBonus/<bonusId>=1`
- `UnlockedUpgrade/<commander>:<upgradeId>=1`

如果要做“槽位式解锁”，也可以加：

- `UnlockedPrestigeSlot/<commander>=1|2|3`

## 实现拆分

### 1. 结算写入

运行时结算需要补三类事实：

- 地图是否首次通关
- 奖励任务 / 成就是否首次达成
- 特殊挑战是否首次完成

以及对应解锁：

- 解锁了哪个威望
- 解锁了哪个额外加成
- 解锁了哪个额外升级

### 2. 启动器读取

`start-7vs1-web-launcher.ps1` 需要从单积分改成双资源：

- 统计军费总收入
- 统计宝石总收入
- 统计精通军费消耗
- 统计威望军费 / 宝石消耗
- 统计额外加成军费 / 宝石消耗
- 校验对应项目是否已解锁

即：

- 未解锁，不允许选
- 已解锁但军费不足，不允许启动
- 已解锁但宝石不足，不允许启动

### 3. 精通结算

精通现在是 6 个槽位，每个槽位 `0..30`。

第一版最直接：

- `masteryCost = 6 个槽位数值总和`

例如：

- `15,15,15,15,15,15` = `军费 -90`
- `30,30,30,30,30,30` = `军费 -180`

如果这个太重，后面再改成：

- 每 2 点精通消耗 1 军费
- 或者按总精通等级做分段

但第一版建议先直算，逻辑最简单。

### 4. 威望结算

当前 WebUI 已经能拿到：

- `prestigeSelections`
- `prestigeBonusMask`

下一步只需要再加：

- 检查该威望是否已解锁
- 根据选中的第几个威望累计军费 / 宝石成本

### 5. 额外加成结算

当前通用加成已经有：

- `genericBonuses`
- `genericBonusLevels`

下一步只需要再加：

- 检查该加成是否已解锁
- 分别累计军费 / 宝石成本

### 6. 额外升级结算

当前需要补一层“可选额外升级”的显式选择数据。

建议新增：

- `selectedCommanderUpgrades`

结构示例：

```json
{
  "Raynor": ["UpgradeA", "UpgradeB"],
  "Kerrigan": ["UpgradeC"]
}
```

然后对每个被选中的升级：

- 检查是否已解锁
- 累计军费 / 宝石消耗

## WebUI 展示

建议把当前积分面板拆成两行：

- `军费：已得 X + 因子 Y - 消耗 Z = 余额 R`
- `宝石：已得 X + 因子 Y - 消耗 Z = 余额 R`

并增加 3 类提示：

- `未解锁`
- `军费不足`
- `宝石不足`

### 交互规则

- 未解锁项：
  - 按钮灰掉
  - 显示解锁来源
- 已解锁但余额不足：
  - 可以显示选中状态预览
  - 但启动按钮禁用

## 特殊挑战建议

特殊挑战不要只给数值，最好一一绑定功能解锁。

建议分三类：

- 解锁威望
  - 例：完成某指挥官挑战后解锁该指挥官第 1 威望
- 解锁额外加成
  - 例：完成全局挑战后解锁 `GuardianShell`
- 解锁额外升级
  - 例：完成指挥官专项挑战后解锁对应 upgrade

这样能保证：

- 通关负责军费
- 因子负责宝石
- 特殊挑战负责“能不能用”

三条线各自有意义，不会互相覆盖。

## 实现顺序

建议按这个顺序做：

1. 启动器先从单积分改成 `军费 + 宝石`
2. WebUI 面板同步改成双余额
3. 精通先接军费消耗
4. 通用加成接双消耗
5. 威望接双消耗
6. 加入解锁表，先控制额外加成
7. 再补威望解锁
8. 最后补额外升级选择与解锁

这样改动最平滑，不会一次全炸。
