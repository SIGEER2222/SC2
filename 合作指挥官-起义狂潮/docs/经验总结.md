# 经验总结

## 2026-06-27 - 指挥官触发器迁移时变量声明问题

**问题**：迁移 Kerrigan 触发器到 KerriganRuntime 后，进图测试报 ScriptError：
```
Script compile error: LibE0EAE146_KerriganRuntime.galaxy (349), 解析函数行出错，可能有无效的变量名/函数调用，或是函数结尾缺失}
脚本代码：    TriggerEnable(libE0EAE146_gt_CM_MasteryKerriganInstantReviveCooldown, false);
```

**原因**：触发器变量（`libE0EAE146_gt_*`）没有在 `LibE0EAE146_h.galaxy` 头文件中声明。Galaxy 脚本中，触发器作为全局变量使用前必须先声明。

**修复**：在 `LibE0EAE146_h.galaxy` 中添加触发器变量声明：
```
trigger libE0EAE146_gt_CM_MasteryKerriganInstantReviveCooldown;
trigger libE0EAE146_gt_KerriganPsiStrike;
trigger libE0EAE146_gt_CM_Kerrigan_WeaponSwap;
```

**教训**：
1. 迁移触发器到 Runtime 文件时，必须同时在头文件 `LibE0EAE146_h.galaxy` 中添加触发器变量声明
2. 不能只检查 Runtime 文件本身是否正确，必须验证头文件中是否有对应的变量声明
3. 每个指挥官迁移后必须进图测试，不能假设代码看起来正确就没问题

## 2026-06-27 - Alarak RuntimeInit 函数位置问题

**问题**：迁移 Alarak 触发器到 AlarakRuntime 后，进图测试报 ScriptError：
```
Script compile error: LibE0EAE146_AlarakRuntime.galaxy (20), 解析函数行出错，可能有无效的变量名/函数调用，或是函数结尾缺失}
         脚本代码：    libE0EAE146_gt_CM_Alarak_Sacrific_Scale_Init();
```

**原因**：Galaxy 脚本中函数必须**先定义后使用**。AlarakRuntime 把 `AlarakRuntimeInit` 放在文件开头，但它调用的各个 `_Init()` 函数都定义在文件后面，导致解析时找不到函数定义。

**修复**：把 `AlarakRuntimeInit` 函数从文件开头移到文件末尾，确保所有被调用的函数都在它之前定义。

**教训**：
1. Galaxy 脚本不支持函数前向声明（除非在头文件中声明），Runtime 文件内的函数必须按调用顺序排列
2. RuntimeInit 作为入口函数，应该放在文件的最后
3. 参考已有的正常工作的 Runtime 文件（如 KerriganRuntime、ZagaraRuntime）的结构来组织代码

## 2026-06-27 - 跨库触发器引用更新问题

**问题**：迁移 Stetmann 触发器到 StetmannRuntime 后，进图测试报 ScriptError：
```
Script compile error: LibKPVP.galaxy (1109), 无效的参数列表
         脚本代码：            libKMIS_gf_CM_Dehaka_SetLevelValues(lp_player);
```

**原因**：`LibKPVP.galaxy` 中引用了 `libKMIS_gt_CM_Stetmann_TriggersInit`，但这个触发器变量已经随迁移从 `LibKMIS_h.galaxy` 中删除了。Galaxy 编译器的错误信息不准确——实际是"未定义的变量"，但错误报在了附近的 Dehaka 函数调用行，显示为"无效的参数列表"。

**修复**：在 `LibKPVP.galaxy` 中将引用更新为新的变量名：
```
libKMIS_gt_CM_Stetmann_TriggersInit  →  libE0EAE146_gt_CM_Stetmann_TriggersInit
```

**教训**：
1. 迁移触发器时，必须搜索整个项目，更新所有对该触发器变量的引用（不只是 LibKMIS 内部）
2. Galaxy 编译器的错误信息可能有偏差，不要完全相信行号和错误描述，要检查附近的代码
3. 常见的跨库引用位置：`LibKPVP.galaxy` 的 StartingTech 函数、`CM_DataUtilInit` 等

## 2026-06-27 - 迁移触发器时变量前缀错误修改问题

**问题**：迁移 Nova 触发器到 NovaRuntime 后，进图测试报 ScriptError：
```
Script compile error: LibE0EAE146_NovaRuntime.galaxy (482), 无效的参数列表
         脚本代码：        libKMIS_gf_CM_ModifyCooldown(...);
```

**原因**：子代理错误地把 Nova 触发器中所有 `libKMIS_gv_` 前缀的变量都改成了 `libE0EAE146_gv_`，但这些变量（如 `cM_NovaGriffinTransportUnit`、`novaBarrackBuilt` 等）仍然定义在 LibKMIS 库中，并没有迁移过来。导致这些变量变成未定义，进而引发编译错误。Galaxy 编译器的错误信息不准确，把变量未定义的问题报成了"无效的参数列表"。

**修复**：将 NovaRuntime.galaxy 中所有被错误修改的变量前缀改回 `libKMIS_gv_`，包括：
- `libKMIS_gv_cM_Nova*` (GriffinTransport 相关变量)
- `libKMIS_gv_NovaPsiStrike*`
- `libKMIS_gv_novaBarrackBuilt`
- `libKMIS_gv_novaFactoryBuilt`
- `libKMIS_gv_novaStarportBuilt`

**教训**：
1. 迁移触发器时，**只修改触发器本身的前缀**（`gt_` 变量和 `gf_` 函数），不要修改触发器内部引用的其他库的变量和函数
2. 变量如果还在原来的库中定义，就保留原来的前缀（如 `libKMIS_gv_`、`libKMIS_gf_`）
3. 只有当变量和函数也一起迁移到新库时，才修改它们的前缀
4. 触发器内部调用的公共库函数（如 `libKMIS_gf_CM_ModifyCooldown`）保持不变

## 2026-06-27 - 文件 UTF-8 BOM 导致全库初始化失败

**问题**：迁移 Zeratul 触发器后，进图测试报 ScriptError：
```
触发器库无法初始化：libKPVP_InitLib (无法找到函数)
触发器库无法初始化：libKCOR_InitLib (无法找到函数)
触发器库无法初始化：libKMIS_InitLib (无法找到函数)
...
脚本读取失败：无法找到函数
```

所有库都无法初始化，看起来像是有严重的编译错误。

**原因**：`LibKMIS_h.galaxy` 文件被添加了 UTF-8 BOM（字节顺序标记，EF BB BF）。BOM 字符位于文件开头，干扰了 Galaxy 脚本编译器，导致它无法正确解析第一行的 `include "LibKCOR_h"` 语句，进而导致整个 LibKMIS 库初始化失败，后续依赖它的所有库也都失败了。

**修复**：移除 `LibKMIS_h.galaxy` 文件的 UTF-8 BOM，使用无 BOM 的 UTF-8 编码保存。

**教训**：
1. Galaxy 脚本文件必须使用 **UTF-8 无 BOM** 编码
2. 当出现"所有库都无法初始化"的错误时，优先检查头文件是否有 BOM 或其他编码问题
3. 使用 PowerShell 的 `Set-Content` 或 .NET 的 `UTF8Encoding(false)` 保存文件时要注意是否会添加 BOM
4. 编辑 Galaxy 脚本后，可以检查文件前 3 个字节是否为 `EF BB BF` 来判断是否有 BOM
5. 跨库的头文件（如 LibKMIS_h.galaxy）如果有问题，会导致所有依赖它的库都初始化失败

## 2026-06-27 - 迁移触发器时遗漏变量声明问题

**问题**：迁移 Nova 触发器后，进图测试报 ScriptError：
```
Script compile error: LibE0EAE146_NovaRuntime.galaxy (482), 无效的参数列表
         脚本代码：        libKMIS_gf_CM_ModifyCooldown(...);
```

**原因**：Nova 触发器中使用了 `novaFactoryBuilt` 和 `novaStarportBuilt` 两个全局变量，但只在头文件中声明了 `novaBarrackBuilt`，遗漏了另外两个变量的声明。Galaxy 编译器的错误信息不准确，把变量未定义的问题报成了"无效的参数列表"，而且行号指向附近的函数调用行。

**修复**：在 `LibE0EAE146_h.galaxy` 中添加缺失的变量声明：
```
int[libKCOR_gv_cCC_MAXPLAYERS + 1] libE0EAE146_gv_novaFactoryBuilt;
int[libKCOR_gv_cCC_MAXPLAYERS + 1] libE0EAE146_gv_novaStarportBuilt;
```

**教训**：
1. 迁移触发器时，要仔细检查触发器中使用的所有全局变量，确保它们都在头文件中声明了
2. 不能只检查触发器本身的声明，还要检查触发器内部引用的所有变量
3. Galaxy 编译器的错误信息不可靠，"无效的参数列表" 可能意味着附近有未定义的变量
4. 对于一组相似的变量（如 novaBarrackBuilt/novaFactoryBuilt/novaStarportBuilt），要确保全部都声明，不要遗漏

## 2026-06-27 - CommanderPowerGenerated 中的跨库触发器引用遗漏

**问题**：修复 Nova 问题后，进图测试报 ScriptError：
```
Script compile error: LibE0EAE146_CommanderPowerGenerated.galaxy (596), 无效的参数列表
         脚本代码：}
```

**原因**：`LibE0EAE146_CommanderPowerGenerated.galaxy` 中引用了 `libKMIS_gt_CM_Stukov_TriggersInit`，但 Stukov 的触发器已经迁移到 E0EAE146 库了，这个变量已经从 LibKMIS_h.galaxy 中删除。之前只更新了 LibKPVP.galaxy 中的引用，遗漏了 CommanderPowerGenerated.galaxy 中的引用。

**修复**：在 `LibE0EAE146_CommanderPowerGenerated.galaxy` 中将引用更新为：
```
libKMIS_gt_CM_Stukov_TriggersInit  →  libE0EAE146_gt_CM_Stukov_TriggersInit
```

**教训**：
1. 迁移触发器时，要搜索**整个项目**中所有对该触发器变量的引用，不只是 LibKPVP.galaxy
2. 常见的引用位置包括：
   - LibKPVP.galaxy 的 StartingTech 函数
   - LibE0EAE146_CommanderPowerGenerated.galaxy 中的 Apply 函数
   - 其他 Runtime 文件中的交叉引用
3. 每次迁移后，都应该用 `grep` 全局搜索 `libKMIS_gt_CM_<指挥官>_TriggersInit`，确保所有引用都已更新
