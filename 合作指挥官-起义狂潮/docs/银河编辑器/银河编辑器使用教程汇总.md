## 一、编辑器概述

### 1.1 什么是银河编辑器

银河编辑器（Galaxy Editor，简称 **GE**）是暴雪娱乐为《星际争霸II》开发的官方地图与 MOD 编辑工具，于 2010 年随游戏同步推出。

- **官方名称**：星际争霸II编辑器（StarCraft II Editor，简称 **SE**）。
- **俗称由来**：开发组内部引擎名为"银河平台引擎"，所用脚本语言叫 **Galaxy**，故社区俗称为"银河编辑器"（GE）。
- **能力定位**：暴雪自用的同款开发工具，提供地形设计、事件触发、数据修改、AI 设定等功能模块，支持图形化界面操作及类 C 语言的 Galaxy 脚本编程，是专业级的游戏引擎，几乎可以编写出一切游戏类型，但必须在星际争霸II战网平台上发布和运行。
- **历史传承**：延续暴雪自 1994 年《魔兽争霸II》起向社区开放创作工具的传统；随版本迭代，1.5.0 新增 UI 与 AI 编辑器，过场动画模块强化了 3D 动画制作能力；后续还开放了包含《魔兽争霸III》全部资源的官方包。

### 1.2 获取与安装

1. 通过战网（Battle.net Desktop App）下载完整的《星际争霸II》游戏本体。
2. 编辑器随游戏附带，在游戏安装目录下找到 `StarCraft II Editor.exe` 即可。
3. **编辑器的使用是免费的**；使用 Starter Edition 即可免费创作。但发布地图到 Battle.net 需要购买《星际争霸II》。

### 1.3 发布与 Arcade

- 玩家可将地图/MOD 发布至暴雪托管的 **Arcade** 平台，供全球玩家发现、游玩、分享。
- 使用 `文件 > 管理已发布...` 查看或移除已发布的地图和 MOD。
- 地图在 Arcade 上显示的游戏类别（如"对战"或"自定义"）以地图的"游戏变量"设置为准（`地图 > 游戏变量...`）。
- 暴雪曾计划支持地图收费/免费形式的商业化运营。

### 1.4 与魔兽争霸3世界编辑器（WE）的对比

| 维度 | 魔兽3 WE | 银河编辑器 GE |
|------|----------|---------------|
| 脚本语言 | JASS | Galaxy（类 C，替代 JASS） |
| 地形 | 纹理较粗，不可直接放"点" | 精细纹理绘制，可直接放置点、可操纵水体、详细光照设置 |
| 触发器 | 功能受限 | 大量本地函数、支持局部变量、最多四维数组、GUI 下自定义函数、可自定义游戏界面 |
| 数据 | 修改受限，常需模拟 | Actor 与物理层面分离，可从底层架构全新机制，可直接制作单位/技能 |
| UI | 仅能改贴图，不能修改 UI | UI 编辑器可调整所有 UI 位置与大小 |
| 内存 | JASS 无垃圾回收，易内存溢出 | 所有本地类型均有垃圾回收系统 |
| 兼容 | — | 可直接导入 SC1 和 War3 地形数据 |

## 二、编辑器模块总览

银河编辑器由多个高度专业化的**模块（Module）**组成，每个模块聚焦游戏开发流程的一个环节。整体协同即可构建完整游戏。

| 模块 | 英文名 | 核心功能 |
|------|--------|----------|
| 地形编辑器 | Terrain Editor | 雕刻地形、绘制纹理、放置点/区域/装饰物/单位，构建游戏世界外观 |
| 触发器编辑器 | Trigger Editor | 编写脚本逻辑（事件/条件/动作），可用 GUI 或 Galaxy 脚本，赋予游戏生命力 |
| 数据编辑器 | Data Editor | 核心之地，存储与创建游戏资产：单位、技能、效果、行为、演算体、武器等 |
| 导入编辑器 | Importer | 导入自定义 3D 模型、图片、音乐等外部资源 |
| UI 编辑器 | UI Editor | 定义/自定义游戏界面，调整 UI 位置与大小 |
| 过场动画编辑器 | Cutscene Editor | 制作游戏内过场动画与 Machinima，媲美官方动画 |
| 文本编辑器 | Text Editor | 管理游戏内文字、多语言翻译、字体样式 |
| AI 编辑器 | AI Editor | 创建/修改人工智能，定义电脑控制单位行为 |

> 模块切换：编辑器顶部模块栏（F5 地形、F6 触发器、F7 数据 等快捷键，可在 `文件 > 配置控制...` 自定义）。

## 三、基本操作与实用提示

### 3.1 通用操作

- **新建文档**：`文件 > 新建...`，选择地形集（Tileset）、依赖项（Dependencies）、地图尺寸。
- **依赖项**：可理解为"资源包"。`Melee (Liberty)` 含标准对战单位；`Campaign (Liberty)` 含战役全部单位（如凯瑞甘、泽拉图、雷诺）及额外环境物件。`文件 > 依赖项...` > `添加标准` 添加战役依赖即可使用战役单位。
- **测试文档**：`文件 > 测试文档`（或快捷键）在游戏中运行当前地图。
- **自动保存**：`文件 > 偏好设置 > 文档` 可配置自动保存与备份。
- **控制台**：`窗口 > 控制台`，输入 `help` 查看可用命令；遇困难可与爱丽莎（AI 助手）交流。
- **总览管理器**：查看文档中正被使用的所有对象或触发器元素。

### 3.2 实用提示精选（37 条）

> 来源：GitHub StarCraft-II-Editor-learning 项目

**依赖与资源**
1. 要使用单人战役单位，在"依赖项"对话框用"添加标准"添加"自由之翼(战役)"依赖项。
2. Mod 中定义的触发器库可通过将库 ID 添加到"触发器库-识别符"栏自动加载：数据模块 > 对象类型选"游戏性数据" > 游戏性值名称找"SC2游戏性默认设定" > 右侧"触发器库-识别符"添加库 ID。
3. 通过"导入"模块导入自己的音效或图片，再在数据和触发器模块中使用。

**测试与调试**
4. 触发器函数"队伍中的玩家"可返回战网游戏房间中分配的队伍相关联的玩家。
5. "触发器调试窗口"非常有用，可帮助找出触发器问题（`文件 > 偏好设定... > 测试文档` 开启）。
6. 触发器可等待的最短时间间隔为 **1/16 秒（0.0625 秒）**，等同于一次游戏循环。
7. 触发器函数"玩家得分值"可获取自动跟踪的所有得分值（如"消灭敌方单位""已采集晶体矿"）。

**地形**
8. 若"地形"模块画面停滞，在 `文件 > 偏好设定 > 视频` 调低视频设置。
9. 沿悬崖边缘喷绘纹理时，"仅限相同的悬崖层级"选项可防止悬崖另一面也应用相同纹理（`工具 > 笔刷 > 仅限相同的悬崖层级`）。
10. "导出地图图片"可将整张地图保存为高质截图（`数据 > 导出地图图片...`）。
11. 用"调整"命令以精确、微量方式调整对象放置区（`编辑 > 调整`）。
12. 多个区域可合并为单个区域使用（`编辑 > 合并框选`）。
13. 启用"允许悬崖合并"可使不同悬崖类型互相重叠或接合（`工具 > 笔刷 > 允许悬崖合并`）。

**触发器与脚本**
14. 自定义脚本元素可在触发器模块中输入任意脚本代码，也可"囊括"额外用"导入"模块导入的脚本文件（`数据 > 新建 > 新建自定义脚本`）。

**数据编辑器**
15. 复制命令允许有选择性地复制或共享所有链接的对象（`数据 > 复制...`）。
16. "对象查看器"可访问与当前对象有关联的所有对象（`查看 > 显示对象查看器`）。
17. 对象查看器中"解释链接"可查看与对象有关联的所有字段（`数据 > 解释链接`）。
18. 高级字段可选：收起保持简洁，展开查看每一行字段（`查看 > 显示高级值`）。
19. 相同结构的子字段列表可一同显示（`查看 > 组合结构值`）。
20. 启用"原始数据显示"查看对象、字段、值的内部数据而非描述性名称（`查看 > 查看原始数据`）。
21. 对象列表可排序列表视图或按类别树状视图显示（`查看 > 以树状图显示对象列表`）。

**数据类型速记**
22. **单位（Unit）**：游戏世界中所有可影响游戏性的对象，含可移动单位、建筑、发射物、可摧毁物体、路径障碍物。
23. **演算体（Actor）**：游戏世界中所有视觉对象或效果，通常与单位或效果关联。
24. **技能（Ability）**：单位可施展的动作，通常通过命令面板按钮实现。
25. **武器（Weapon）**：单位所进行的攻击类型。
26. **行为（Behavior）**：可对单位应用的被动效果或状态。
27. **效果（Effect）**：个体视觉或游戏性效果，用于定义技能和行为。

**其他**
28. "对象组"对话框可预先定义触发器中使用的单位组（`地图 > 对象组...`）。
29. 地图游戏类别按"游戏变量"设置为准（`地图 > 游戏变量...`）。
30. 文本模块可对地图/MOD 中所有文本执行拼写检查（`数据 > 拼写检查...`）。
31. 所有命令快捷键均可自定义，也可为无快捷键命令添加（`文件 > 配置控制...`）。
32. 编辑器控制台输入 `help` 查看命令列表（`窗口 > 控制台`）。

## 四、地形编辑器（Terrain Editor）

### 4.1 概述与图层

地形编辑器是编辑器默认首先打开的窗口，用于制作/修改地图地形，并放置点、区域、单位、演算体、地形物件等。内容归类于不同**层（Layer）**：

- **地形层**：修改地图布局与环境（地面纹理、地形高低、悬崖、水体等）。
- **单位层**：放置单位、建筑。
- **装饰物层（Doodad/物件）**：放置树木、岩石等环境物件。
- 还有点、区域等层。

> 注：与魔兽3不同，银河编辑器的地形有时并非必须——利用触发器完全可以做出不需要地形的游戏。

### 4.2 笔刷工具（Brush）

编辑器中任何添加、修改、移除地形/纹理/单位等的工具统称为**笔刷（Brush）**。左侧小地图下方有一排笔刷按钮：

| 笔刷 | 功能 | 快捷操作 |
|------|------|----------|
| 纹理（Texture） | 绘制地面纹理 | 最左侧按钮，按 `[T]` 进地形层 |
| 高度（Height） | 抬升/降低地形，造丘陵、山谷、弹坑 | 蓝色小山图标 |
| 悬崖（Cliff） | 创建悬崖、斜坡 | 悬崖+绿色上箭头 |
| 水体（Water） | 添加/移除水面 | 水滴图标 |
| 道路（Road） | 铺设道路 | — |
| 植被（Foliage） | 生成草、花等小植被 | 树图标 |

每个笔刷有多个**操作（Operation）**（如悬崖笔刷有 Lower Cliff / Raise Cliff / Add Ramp），可设置笔刷大小、形状、增量（Increment）、速度（Speed）等参数。

### 4.3 悬崖与高度

- **降低悬崖（Lower Cliff）**：将地形向下推，创建峡谷。
- **抬高悬崖（Raise Cliff）**：创建抬升的人造悬崖（如停机坪）。
- **添加斜坡（Add Ramp）**：斜坡只能画在悬崖边缘，不能画在平地。
- **高度笔刷**：在不制造悬崖的情况下抬升/降低地形，造丘陵、山谷。可用**平滑（Smooth）**操作消除高度笔刷留下的尖锐边缘。

### 4.4 纹理

- 选择纹理笔刷，操作含 Add Texture / Remove Texture / Blend（混合）/ Smudge（涂抹）/ Fill（填充）等。
- 参数：Increment（绘制速度）、Size（笔刷半径）、Speed。
- 可在停机坪铺水泥，周围铺草地、泥路等。

### 4.5 水体

- 水体笔刷操作仅有 Add Water / Remove Water。
- 添加后水面可能浮在峡谷上方，用 **Edit Water** 按钮打开水面设置，调整 **Height** 滑块至水面舒适地落在沟渠中。
- 水面设置含多种选项（流速、颜色等）可调。

### 4.6 道路（Road Tiles）

- 道路笔刷每个地形集只有一种操作和一种类型。
- 左键放置道路点，道路点会自动连接附近道路点；按住 `Control` 放置不连接的独立点。
- 进入**选择模式**（按 `空格` 或 `Esc`）可看到绿色金字塔道路点，拖动可移动，`Control`+左键拖动可旋转。
- ⚠️ 道路不会显示在小地图上，需在道路下方绘制水泥纹理提示玩家路径。

### 4.7 植被（Foliage）

- 大型植被（树、灌木）由设计师手动放置；小型植被（草、花）用**植被生成器**批量生成，性能远优于手动放置成千上万个草物件。
- ⚠️ 植被在"低"画质设置下不可见，由"地形质量"设置决定是否显示。
- 操作：选择密度（如 0.50）后点 Generate Foliage 生成。
- 用 **Disallow Foliage** 操作绘制禁止植被区域（如道路上），再切回 Allow Foliage 重新生成。

### 4.8 视角与操作技巧

- **移动地图视角**：按住右键拖动。
- 沿悬崖喷绘纹理启用"仅限相同的悬崖层级"防止纹理穿透。
- 导出整张地图为高质截图：`数据 > 导出地图图片...`。
- 地形画面卡顿可调低视频设置（`文件 > 偏好设定 > 视频`）。

## 五、触发器编辑器（Trigger Editor）

### 5.1 概述

触发器编辑器是用来编写脚本、实现各种事件的模块，是赋予游戏"生命力与逻辑"的核心。它能设计剧情、设定玩法、改写游戏界面，能力随补丁更新不断增强——从魔兽世界式的 WSAD 移动、CS 式射击，到连连看、斗地主等纯图形游戏均可实现。

- 运行地图时，触发器文件会自动转换为 Galaxy 脚本。
- 触发器使用 **Galaxy** 语言（类 C），同时提供强大的 **GUI 图形化界面**，可实现代码 99.9% 的功能，无需编写 galaxy 脚本甚至无需了解 C 语言。
- 相比魔兽3 JASS：本地函数更多、变量声明更科学、支持局部变量、最多四维数组、GUI 下支持自定义函数、语法更现代、支持自定义游戏界面。

### 5.2 ECA 结构

触发器采用 **ECA 结构**：

- **事件（Event）**：触发器的开始，定义"何时"触发（如"单位死亡""玩家按下按键""每 2 秒"）。
- **条件（Condition）**：需要满足的要求，全部条件为真时才执行动作。支持 And / Or / Not 逻辑组合。
- **动作（Action）**：触发器的输出结果，满足条件后执行的操作（如创建单位、显示文本、播放音效）。

### 5.3 GUI 与自定义脚本

- **GUI**：图形化编辑，通过选择函数/动作块拼接逻辑，无需写代码，新手友好。
- **自定义脚本元素**：可在触发器中输入任意 Galaxy 脚本代码，也可 `include` 用"导入"模块导入的脚本文件（`数据 > 新建 > 新建自定义脚本`）。
- 触发器编辑器支持自定义函数（动作元素和条件元素均可自定义），可基于其他动作或脚本创建自己的动作元素。

### 5.4 变量与函数

- **变量声明**：支持全局变量与**局部变量**（JASS 无局部变量或需手动置空）。
- **数组**：支持最多**四维数组**。
- **函数**：大量原生（本地）函数可二次开发；支持 GUI 下自定义函数。
- 最短等待间隔 1/16 秒（0.0625 秒）= 一次游戏循环。

### 5.5 触发器类别与库

- 触发器可组织为不同**类别（Category）**便于管理。
- 触发器**库（Library）**可复用、可被 Mod 自动加载（通过数据编辑器"触发器库-识别符"）。
- 自定义脚本可用 `include "TriggerLibs/xxx"` 引入外部脚本文件。

### 5.6 常用技巧

- 开启"触发器调试窗口"排查问题。
- 用"玩家得分值"获取消灭敌方单位、已采集晶体矿等分数。
- 用"队伍中的玩家"获取战网房间分配的队伍玩家。

## 六、数据编辑器（Data Editor）

### 6.1 概述

数据编辑器是银河编辑器的**核心之地**，也是最难上手、最复杂的部分。利用它可从游戏底层开始架构全新而完善的游戏机制，而无需依赖触发器。

- 编辑器使用 **XML 文本**储存资料，并以 GUI 形式显示（也可直接修改 XML）。
- 资料类型极多，一切与星际2有关的资料都可从此修改。
- 1.4.0 / 1.5.0 / 2.0.0 / 2.1.0 补丁均对数据编辑器进行了重大强化，务必使用最新版。

### 6.2 核心数据类型

| 数据类型 | 说明 |
|----------|------|
| **单位（Unit）** | 游戏世界中可影响游戏性的对象：可移动单位、建筑、发射物、可摧毁物体、路径障碍物 |
| **演算体（Actor）** | 游戏世界中的视觉对象或效果，通常与单位或效果关联 |
| **技能（Ability）** | 单位可施展的动作，通常通过命令面板按钮实现 |
| **武器（Weapon）** | 单位的攻击类型 |
| **行为（Behavior）** | 可对单位应用的被动效果或状态（BUFF/DEBUFF） |
| **效果（Effect）** | 个体视觉或游戏性效果，用于定义技能和行为 |

> 技能是一种带有一串指令的数据模块，通常通过按钮与单位连接；按下按钮便执行技能中定义好的指令。攻击技能即使没有命令面板按钮，单位也需要它才能使用武器（除非武器禁用了"需要开启的攻击技能"标旗）。

### 6.3 Actor 演算体系统

Actor（GA 译：演算体）是数据编辑器相对前作最大的进步。**Actor 不是模型，也不是单位，而是控制游戏画面和声音资源的中间层**：

- 通过触发器式的事件生效，能对模型和声音进行精确操控。
- 例：让盾牌围绕单位旋转飞行——单位无围绕旋转的附着点，盾牌也无特殊动画。旧时代需用 3ds Max 改模型（增加制作难度和游戏体积），银河编辑器只需两三个 Actor 指令即可完成。
- **Actor 层面与物理层面分离**，可修改游戏底层数据，可完全从基础制作单位或技能而无需模拟。

### 6.4 XML 与原始数据

- 数据以 XML 储存，可在 GUI 编辑，也可直接改 XML。
- 启用"原始数据显示"（`查看 > 查看原始数据`）查看内部数据 ID 而非描述性名称——对查阅/复制/排错非常重要。
- 高级字段可选展开/收起（`查看 > 显示高级值`）。
- 相同结构子字段可组合显示（`查看 > 组合结构值`）。

### 6.5 复制与链接

- **复制命令**（`数据 > 复制...`）允许有选择性地复制或共享所有链接的对象——GE 复制功能不如 WE 人性化，需理解物编链接原理。
- **对象查看器**（`查看 > 显示对象查看器`）：访问与当前对象关联的所有对象。
- **解释链接**（`数据 > 解释链接`）：查看与对象关联的所有字段。
- 新手复制单位/武器/技能时常因链接处理不当产生 BUG，需先理解数据链接机制。

### 6.6 制作单位/技能/效果流程（概要）

1. 打开数据面板，进入对应数据类型页面（如单位）。
2. 右键空白处添加对象，设置名称及各字段值。
3. 配套制作武器、技能、效果、行为、演算体等关联对象，正确建立链接。
4. 将技能链接到单位命令面板按钮。
5. 复制现有对象作为基底再修改，比从零开始更高效（注意复制时选择需共享的链接）。
6. 用对象查看器与解释链接检查所有关联是否正确。

## 七、Galaxy 脚本语言

### 7.1 概述

Galaxy（银河语言）是暴雪为星际II地图编辑器开发的**类 C 脚本语言**，替代了魔兽3的 JASS 语言。触发器 GUI 最终会转换为 Galaxy 脚本运行。

- 任何熟悉 C 语言的人都能很快上手。
- 支持基于事件的自定义函数与本地函数的二次开发。
- 提供**基于所有本地类型的垃圾回收系统**，解决了 JASS 内存溢出问题（JASS 技术上根本没有垃圾回收）。
- 非面向对象；多数本地函数基于对游戏对象操作。

### 7.2 语言特性

- 采用类似老式 C 语言的语法结构。
- **选择结构与循环体必须使用大括号 `{}` 包裹**，即便只有一行也不能省略。
  - 错误：`if(1==1) UIDisplayMessage(...);`
  - 正确：`if(1==1) { UIDisplayMessage(...); }`

### 7.3 与 C 语言的区别（18 点）

1. 没有 `float` 和 `double`，只有一个 **`fixed`** 类型（定点小数）。
2. 使用老式 C 语法，**变量必须声明在顶部**。
3. 数组尺寸写在**类型后面**而非变量名后：`int[3] abc;`（正确）vs `int abc[3];`（错误）。支持多维：`int[3][4] abc;` 合法。
4. **不支持括号强制类型转换**（如 `(int)1.23`），只能用原生函数转换；因此也无法定义函数指针。
5. **不支持 `++` 和 `--`** 操作。
6. 指针无法自增/自减，也无法用 `p+1` 改变指针值（1 被识别为整数，不会自动转为指针）。
7. **不支持 `/* */` 注释块**，只支持单行注释 `//`。
8. **不支持预处理指令**。
9. 没有 `#include`，使用 `include "TriggerLibs/MeleeNotHardAI"` 形式（无 `#`，不写 `.galaxy` 后缀）。
10. **不支持 `goto`** 语句。
11. 不支持 `new`（C 本就无此关键字，属 C++）。
12. **不支持动态内存分配**，无法 `malloc()`。
13. 不支持 `sizeof`（无法 malloc 则 sizeof 也无意义）。
14. 没有 `signed`/`unsigned`，所有数值类型默认有符号。
15. **不支持 `switch`**，只能用 `if`。
16. **不支持 `for` 循环**，只能用 `while`。
17. 表达式 `(null=="")` 返回真（二者确为不同值）。
18. 所有 `if` 选择分支和 `while` 循环体必须写在大括号内，单行也不能省略。

### 7.4 include 与库

- 引用方式：`include "TriggerLibs/MeleeNotHardAI"`（无 `#`，无后缀）。
- 可在触发器模块用自定义脚本元素引入用"导入"模块导入的脚本文件。
- Mod 中的触发器库可通过数据编辑器"触发器库-识别符"自动加载。

### 7.5 垃圾回收

- Galaxy 拥有适用于所有本地类型的强大垃圾回收系统。
- JASS 中局部变量用完需置空、点对象需手动删除以防溢出——这些问题在 Galaxy 中成为历史。

### 7.6 官方问答要点

- **是否事件驱动/面向对象**：多数本地函数基于游戏对象操作，但语言本身不面向对象。
- **自定义界面**：游戏 UI 设定大部分放在数据文件中，编辑器不支持直接修改这些文件，自定义 UI 可行但不便操作（UI 编辑器可辅助）。
- **触发器事件通讯**：触发编辑器显著更新是支持自定义函数（动作和条件元素均可自定义）。
- **英雄单位**：提供比魔兽3更灵活好用的英雄编辑系统，可修改任何自定义属性数值。
- **公共 API 函数**：与魔兽3一样有大量反映游戏功能的本地函数可供二次开发。

## 八、其他模块

### 8.1 UI 编辑器（UI Editor）

- 1.5.0 补丁新增模块，2.0.0 后支持 GUI。
- 可调整游戏中所有 UI 的位置和大小（如小地图放右上、控制按钮下方排列）。
- 仅支持 XML 界面编辑（2.0.0 起支持 GUI）。
- 相比魔兽3 WE（压根不能修改 UI，仅改贴图）是重大进步。

### 8.2 文本编辑器（Text Editor）

- 管理游戏内所有文本。Galaxy 和数据编辑器 XML 不直接支持多语言，需将外语（如中文）封装成条目并在触发器/数据编辑器中引用。编写触发器和数据时输入的中文会自动转化为文本文件保存于此。
- 可定义游戏内字体样式。
- 可执行拼写检查（`数据 > 拼写检查...`）。
- 方便翻译外国地图。

### 8.3 导入编辑器（Importer）

- 往地图注入非星际2自带内容：自制图标、模型、音乐等。
- 支持格式：**M3** 模型、**OGG/MP3** 音效、**TGA/DDS** 图片。
- 操作比魔兽3 WE 方便很多，尤其分块制作地图时。
- 模型需用 3ds Max/Maya 制作后用 Startools 转为 M3；编辑器内置模型预览器含基础修改功能（组合模型、附加粒子、录制等）。

### 8.4 AI 编辑器（AI Editor）

- 1.5.0 补丁新增模块。
- 设定基础游戏 AI；更复杂的"智能 AI"仍需用触发器自行编写，没有傻瓜化模板。
- 与魔兽3 WE 类似，都是设定最基础 AI 的地方。

### 8.5 过场动画编辑器（Cutscene Editor）

- 暴雪早已开发，1.5.0 补丁后正式放出。
- 可制作媲美星际2任务关的栩栩如生、仅次于 CG 的游戏过场动画。
- 让 GE 看起来更像强大游戏引擎而非地图编辑器。
- 使用简单，有官方教程；亦可用于纯 3D 动画制作（Machinima）。
- 星际2过场动画与魔兽3完全是两个档次。

## 九、可制作游戏类型与玩家设定

### 9.1 可制作游戏类型

银河编辑器可制作的游戏类型极广（编辑器是开发工具，给的是可能性而非内置模板；因脚本不支持对象封装，做某些游戏类型可能比用独立游戏引擎还难）：

| 类型 | 缩写 | 类型 | 缩写 |
|------|------|------|------|
| 动作/平台动作/动作射击 | ACT | 角色扮演 | RPG |
| 对战格斗 | FTG | 动作角色扮演 | ARPG |
| 射击/光枪射击 | STG | 策略角色扮演 | SRPG |
| 主视点射击 | FPS | 网络角色扮演 | MMORPG |
| 第三人称射击 | TPS | 文字冒险 | AVG |
| 策略 | SLG | 动作冒险 | AAVG |
| 即时战略 | RTS | 模拟育成/经营 | SIM |
| 体育 | SPG | 竞速 | RAC |
| 益智 | PUZ | 音乐/节奏 | MUG |

> 典型案例：可做星际2版 CS、越肩视角游戏、连连看、斗地主、塔防、RPG 史诗；风暴英雄（Heroes of the Storm）的原型即建于星际II编辑器中。

### 9.2 玩家设定

- 支持最多 **14 名玩家 + 2 名中立电脑玩家**。
- **不支持游戏内加入玩家**，无法做出陆续有玩家进出的大型连续式网络游戏；但房间式网络游戏可行。
- 地图可自定义界面（如官方星宝迷阵、失落的维京战机）。

### 9.3 Bank 存档系统

- 支持游戏存档（Bank）系统：多人游戏完成后，下次进入可继续上次进度，也可保存玩家积分。
- Bank 文件储存在**玩家本地电脑**，作者应进行加密处理防止作弊。

## 十、学习路径与资源指引

### 10.1 推荐学习顺序

1. **地形编辑器**（最易上手）：掌握图层、笔刷、悬崖、纹理、水体、植被。
2. **触发器编辑器**（GUI 入门）：理解 ECA 结构，学会用 GUI 拼接逻辑。
3. **数据编辑器**（核心进阶）：从复制现有单位/技能改起，理解链接与 Actor 系统。
4. **Galaxy 脚本**（高级）：在 GUI 基础上学习自定义脚本，掌握语法差异。
5. **UI/文本/导入/AI/过场动画**：按需深入。
