# 运行时动态修改对比报告

> 目的：解释"扫描结果 vs 游戏内实际"差异的根源
> 生成日期：2026-07-02
> 搜索范围：`Mods\7vs1\CoopZeroPop.SC2Mod\Base.SC2Data\` 下所有 galaxy 脚本

## 核心结论

**静态 XML 扫描能看到的**：能力/单位的"定义"是否存在
**运行时动态修改的三类**：
1. `TechTreeUnitAllow` / `TechTreeAbilityAllow` — 科技树解锁/锁定（XML 有定义，但游戏里需要解锁才能用）
2. `UnitAbilityAdd` — 真正给单位添加新能力（XML 里完全没有，扫描看不到）
3. `CatalogFieldValueSet` — 修改字段值（扫描的是原始值，运行时是改后的值）

## 六、关键单位差异详解

### 6.1 BrutaliskAbathur（阿巴瑟莽兽）

**扫描结果**：
- 能力：仅 CAbilQueue(que1)
- 被生产由：EvolveToBrutalisk

**运行时实际**：
- 上述 + 3 个 Purchase 能力（TramplingCarapace/SavageRend/FleshRecomposition）
- 上述 + 5 个 Strain 能力（如果归类为 Roach 系则会注入）

**差异根源**：`AbathurRebornAddPurchaseAbilities` 在单位出生事件中 `UnitAbilityAdd`

### 6.2 LarvaAbathur（阿巴瑟幼虫）

**扫描结果**：无静态关联

**运行时实际**：
- 通过 `TechTreeUnitAllow(player, "LarvaAbathur", true)` 启用
- 变异目标通过 `TechTreeAbilityAllow` 解锁 EvolveToBrutalisk 等

**差异根源**：LarvaAbathur 的变异能力定义在通用 AbilData.xml（EvolveToBrutalisk 等），但需要 TechTree 解锁才能在幼虫面板出现

### 6.3 LarvaKerrigan（凯瑞甘幼虫）

**扫描结果**：6 个变异单位（Drone/Zergling/Overlord/Hydralisk/Ultralisk/Mutalisk）

**运行时实际**：
- 上述 + 可能的眼虫（通过 CatalogFieldValueSet 动态设置能力字段）
- 所有变异能力需要 TechTreeAbilityAllow 解锁

**差异根源**：眼虫可能通过 CatalogFieldValueSet 动态注入到 LarvaTrain 的某个 cmd index

### 6.4 SCVSwann（斯旺 SCV）

**扫描结果**：16 个可建造建筑（含 5 个斯旺特色炮塔）

**运行时实际**：与扫描一致，但需要 `TechTreeUnitAllow(player, "SCVSwann", true)` 启用 SCV 本身

**差异根源**：无，扫描准确

## 八、工具改进方向

若要让扫描工具反映运行时实际，可考虑：

1. **解析 galaxy 脚本的 UnitAbilityAdd 调用**：提取 `UnitAbilityAdd(unit, "AbilId")` 模式，把动态注入的能力加到对应单位的 abilities 列表
2. **解析 TechTreeAllow 调用**：标记哪些单位/能力是"需解锁"状态
3. **解析 CatalogFieldValueSet 调用**：覆盖扫描到的原始字段值
4. **按指挥官 TechFilter 分组**：模拟 ApplyTechFilter 逻辑，输出每个指挥官实际可用的单位/能力清单

目前工具已标注"仅静态分析 GameData XML，不解析 galaxy 脚本运行时调用"的局限，本报告即为此局限的具体量化。
