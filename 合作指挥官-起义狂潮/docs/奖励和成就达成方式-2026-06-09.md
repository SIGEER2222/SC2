# 奖励和成就达成方式

记录日期：2026-06-09

本文只记录当前代码已经实现的条件，来源为 `Mods/7vs1/CoopZeroPop.SC2Mod/Base.SC2Data/LibE0EAE146_ProgressionRewards.galaxy` 和 `LibE0EAE146.galaxy`。未写事件源或未写阈值的内容不按设计推断。

## 生命周期入口

- 初始化：`Initialize` 调用 `XMProgression_Init(1)`，读取 `CampaignXCore.SC2Bank` 的 `Blessing/Selected` 和 `Challenge/Active`。
- 开局：`StartGame` 调用 `XMBlessing_ApplySelected(1)`，应用已选择且已解锁的祝福。
- 胜利：`FinishLevel` 调用 `XMProgression_RecordVictory(1, mapId, commanderId, bonusScore, heroDeaths)`，写入通关、成就、奖励和挑战结算。

## 通关成就

- `ACH_CLEAR_ANY_MISSION`：任意地图胜利。
- `ACH_CLEAR_<mapId>`：胜利时按当前地图 ID 解锁，例如 `ACH_CLEAR_ttosh02`。
- `ACH_COMMANDER_<commanderId>_CLEAR`：胜利时按当前指挥官 ID 解锁，例如 `ACH_COMMANDER_TerranRaynor_CLEAR`。
- `ACH_FULL_BONUS_CLEAR`：胜利时 `bonusScore >= 3`。
- `ACH_NO_HERO_DEATH_CLEAR`：胜利时 `heroDeaths <= 0`。
- `ACH_CLEAR_5_MISSIONS`：累计胜利次数 `Progression/TotalWins >= 5`。

## 奖励解锁

- `RewardVictoryArchive`：任意胜利直接写入 `Reward/RewardVictoryArchive = 1`。
- `RewardGuardianShell`：累计胜利次数达到 5 时解锁。
- `RewardResourceRich`：激活挑战 `ChallengeResourceScarce` 并胜利。
- `RewardGoldenMinerals`：激活挑战 `ChallengeSpeedClear` 并胜利。

## 祝福解锁

- `BlessingGuardianShell`：累计胜利次数达到 5 时解锁。
- `BlessingResourceRich`：激活挑战 `ChallengeResourceScarce` 并胜利。
- `BlessingGoldenMinerals`：激活挑战 `ChallengeSpeedClear` 并胜利。
- `BlessingPhaseRepair`：当前只在 `XMProgression_DebugUnlockFirstBatch` 调试函数里解锁，正常流程暂无达成条件。
- `BlessingCreepRegeneration`：当前只在 `XMProgression_DebugUnlockFirstBatch` 调试函数里解锁，正常流程暂无达成条件。

## 挑战成就

- `ACH_CHALLENGE_RESOURCE_SCARCE_CLEAR`：`Challenge/Active == ChallengeResourceScarce` 且胜利。
- `ACH_CHALLENGE_SPEED_CLEAR`：`Challenge/Active == ChallengeSpeedClear` 且胜利。
- `ACH_CHALLENGE_FULL_BONUS_CLEAR`：`Challenge/Active == ChallengeFullBonus`，胜利且 `bonusScore >= 3`。
- `ACH_CHALLENGE_NO_HERO_DEATH_CLEAR`：`Challenge/Active == ChallengeNoHeroDeath`，胜利且 `heroDeaths <= 0`。

## 祝福效果

- `BlessingResourceRich`：开局一次性给玩家 1 增加 500 晶矿和 200 气。
- `BlessingGoldenMinerals`：开局一次性给玩家 1 增加 1000 晶矿。
- `BlessingGuardianShell`：开局对玩家 1 当前己方单位执行一次性缓冲，最多恢复 25 生命和 25 护盾；这不是死亡免疫。
- `BlessingPhaseRepair`：每 2 秒给玩家 1 机械单位恢复 3 生命。
- `BlessingCreepRegeneration`：每 2 秒给玩家 1 生物单位恢复 2 生命。

## 银行键

- 成就：`Achievement/<AchievementId> = 1`。
- 成就进度：`AchievementProgress/<AchievementId> = value`。
- 奖励：`Reward/<RewardId> = 1`。
- 祝福解锁：`Blessing/<BlessingId> = 1`。
- 祝福选择：`Blessing/Selected = <BlessingId>`。
- 挑战选择：`Challenge/Active = <ChallengeId>`。
- 挑战最佳时间：`ChallengeBest/<ChallengeId>:<mapId> = clearTime`，只在首次或更快通关时更新。
- 地图通关：`MapClear/<mapId> = 1`。
- 地图最佳时间：`MapBest/<mapId> = clearTime`，只在首次或更快通关时更新。
- 指挥官地图通关：`CommanderClear/<commanderId>:<mapId> = 1`。
- 指挥官任务状态：`Progression/ObjectiveState/<commanderId>:<mapId>:<Main|Minor>:<index> = state`，`2` 表示完成，`3` 表示失败。
- 总胜场：`Progression/TotalWins`。
- 最近通关：`Progression/LastClearTime`、`Progression/LastCommander`、`Progression/LastMap`。

## Review 问题

- `ChallengeSpeedClear` 当前没有时间阈值，只要选中该挑战并胜利就算完成。
- `ChallengeResourceScarce` 当前没有资源采集、消耗或剩余资源限制，只要选中该挑战并胜利就算完成。
- `XMBlessing_SelectForNextRun` 会在选择非空祝福时直接 `XMBlessing_Unlock`，UI 如果直接调用它会绕过祝福解锁条件。
- `BlessingGuardianShell` 名称容易被理解为阿塔尼斯守护之壳，但当前实现只是开局一次性生命/护盾缓冲。
- `XMChallenge_RecordEvent` 只把事件值加到 `AchievementProgress`，当前没有看到实际挑战事件源调用它。
- `BlessingPhaseRepair` 和 `BlessingCreepRegeneration` 有效果但没有正常解锁路径。

## 未证明边界

- 当前加载级烟测只证明无新增 crash、无新增 ScriptError、非黑屏；没有触发 `FinishLevel`，所以不能证明胜利奖励已在实机中写入银行。
- 现有条件来自静态代码检查；祝福数值是否符合设计和平衡需要后续 review。
- 如要做完整守护之壳死亡免疫，需要单独新增数据行为或死亡事件模块，不能把当前缓冲效果当作最终实现。
