# 启动测试说明 - 2026-06-07

## 当前可直接用的脚本

- `scripts/start-7vs1-launcher.ps1`
  - 本地 WinForms 初始界面。可选择地图、单个指挥官、威望奖励、精通等级/6 个精通槽、多个因子，然后调用现有启动脚本开始游戏。

- `scripts/launch-7vs1-coop-test.ps1`
  - 把选定 `_7vs1` 地图和 `Mods/7vs1` 运行库安装到 SC2 live 目录，然后启动地图。

- `scripts/capture-7vs1-ingame-smoke.ps1`
  - 自动启动后等待一段时间，抓图并记录 `ScriptError` / `Crash` / `Alerts` / `login_required`。

## 图形初始界面

在 `E:\Code\MyMod\SC2\合作指挥官-起义狂潮` 根目录执行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-7vs1-launcher.ps1
```

界面数据来源：

- 地图：自动扫描 `Maps/*_7vs1.SC2Map`。
- 指挥官、威望名、精通槽名：读取 `Shared/CommanderPower/commander-power-metadata.json`。
- 因子：解析 `scripts/launch-7vs1-coop-test.ps1` 中的 69 个银行注入白名单。

提交后会后台调用：

- `scripts/launch-7vs1-coop-test.ps1`

并把 stdout/stderr 写到：

- `logs/launcher-*.stdout.txt`
- `logs/launcher-*.stderr.txt`

自检入口：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-7vs1-launcher.ps1 -SelfTest
```

当前界面是单指挥官启动器；`ttosh02_7vs1` 这类保留原任务敌方槽位的图，启动脚本本身也要求一次测试一个指挥官。多指挥官组队选择后续可以在界面上扩展，但需要按地图类型区分。

## 目标目录直接手动开图

在 `E:\Code\MyMod\SC2\合作指挥官-起义狂潮` 根目录执行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\launch-7vs1-coop-test.ps1 `
  -MapSource "Maps\ttosh02_7vs1.SC2Map" `
  -LiveMapName "ttosh02_7vs1.SC2Map" `
  -Commanders TerranRaynor
```

换图时只改 `MapSource` 和 `LiveMapName`，例如：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\launch-7vs1-coop-test.ps1 `
  -MapSource "Maps\thanson01_7vs1.SC2Map" `
  -LiveMapName "thanson01_7vs1.SC2Map" `
  -Commanders TerranRaynor
```

## 自动烟测

在目标目录根目录执行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\capture-7vs1-ingame-smoke.ps1 `
  -MapSource "Maps\ttosh02_7vs1.SC2Map" `
  -LiveMapName "ttosh02_7vs1.SC2Map" `
  -Commanders TerranRaynor
```

注意：

- `launch-7vs1-coop-test.ps1` 和 `capture-7vs1-ingame-smoke.ps1` 默认共用同一个 SC2 live 安装目录。
- 不要并行跑多份启动/烟测脚本，否则会在 live `Maps/`、`Mods/` 安装阶段互相覆盖，出现伪报错。
- 这两类脚本应串行执行。

## 指挥官威望 / 精通测试入口

`launch-7vs1-coop-test.ps1` 现在会在启动前直接写 `CampaignXCore.SC2Bank` 的 `CommanderPower` 段，作为当前统一的威望/精通测试入口。

当前默认值：

- `-CommanderPowerProfile AllPositiveFusion`
- `-CommanderPowerPrestigeBonusMask 7`
- `-CommanderPowerMasteryLevel 30`

也就是：

- 默认三威望正收益全开
- 默认 6 项精通全满
- 默认不施加官方威望负面代价

### 常用例子

默认三威望正收益全开 + 精通全满：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\launch-7vs1-coop-test.ps1 `
  -MapSource "Maps\ttosh02_7vs1.SC2Map" `
  -LiveMapName "ttosh02_7vs1.SC2Map" `
  -Commanders TerranRaynor
```

单独覆盖某个精通值，例如把雷诺第 1 项精通改成 `17`：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\launch-7vs1-coop-test.ps1 `
  -MapSource "Maps\ttosh02_7vs1.SC2Map" `
  -LiveMapName "ttosh02_7vs1.SC2Map" `
  -Commanders TerranRaynor `
  -CommanderPowerOverride Raynor.Mastery0=17
```

只开部分威望正收益，例如只开第 1 和第 3 个威望正收益：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\launch-7vs1-coop-test.ps1 `
  -MapSource "Maps\ttosh02_7vs1.SC2Map" `
  -LiveMapName "ttosh02_7vs1.SC2Map" `
  -Commanders TerranRaynor `
  -CommanderPowerPrestigeBonusMask 5
```

如果后续需要测试“带官方负面代价”的 profile，不再使用 `AllPositiveFusion`，而是改 `-CommanderPowerProfile` 为其它名字，再配合 `-CommanderPowerPrestigeBonusMask` / `-CommanderPowerPrestigePointIndex` / `-CommanderPowerOverride` 细化。

### 当前支持的 bank 键

按指挥官写入 `CommanderPower` 段，键格式如下：

- `<Commander>.Profile`
- `<Commander>.PrestigeBonusMask`
- `<Commander>.PrestigePointIndex`
- `<Commander>.PrestigeIndex`（兼容键）
- `<Commander>.PrestigeMask`（兼容键）
- `<Commander>.MasteryDefault`
- `<Commander>.Mastery0` 到 `<Commander>.Mastery5`

旧字段名 `PrestigeMask` / `PrestigeIndex` 仍保留兼容，方便历史 preset 和旧验证脚本继续读写。

当前测试脚本会把 `TerranRaynor` / `ZergKerrigan` 这类测试名自动映射到 `Raynor` / `Kerrigan` 这类 `CommanderPower` bank key。

### CommanderPower 元数据

当前 18 个官方指挥官的结构化威望/精通元数据固定落在：

- `Shared/CommanderPower/commander-power-metadata.json`

刷新元数据：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\export-commander-power-metadata.ps1
```

校验元数据和协议层是否一致：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-commander-power-metadata.ps1
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-commander-power-runtime-coverage.ps1
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-commander-power-protocol.ps1
```

全量 bank/安装矩阵：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-7vs1-commander-power.ps1 `
  -IncludePrestigeBonusMaskMatrix `
  -IncludeMasteryOverrideSmoke
```

旧开关 `-IncludePrestigeMaskMatrix` 仍作为 alias 保留，方便复用历史命令；新测试和文档统一使用 `-IncludePrestigeBonusMaskMatrix`。

这份元数据当前已经包含：

- `runtime_commander`
- `bank_commander`
- `generated_commander`
- 3 个威望的 `slot / bit_mask / button_id / name / tooltip / primary_upgrade`
- 6 个精通的固定槽位顺序、`upgrade`、`category`、`point_increments`
- 对应的 concrete bank keys

`validate-commander-power-preset-file.ps1` 默认走 `Maps\thanson01_7vs1.SC2Map`，因为 `ttosh02_7vs1.SC2Map` 仍保留原始敌方槽位布局，只适合单指挥官测试。

### 当前测试保留机制

- `CoopZeroPop` 现在会在真实大厅初始化时，把官方指挥官选择、威望和精通同步写回 `CommanderPower`。
- 为了让脚本测试仍然能强制使用 bank 预设，`launch-7vs1-coop-test.ps1` 额外写入：
  - `CommanderPowerRuntime/PreserveBankPreset`
- 它是一次性递减开关：
  - 当前脚本按本次测试写入的指挥官数设置次数。
  - 本局游戏里 `CoopZeroPop` 会先消费这个次数，再跳过 lobby bridge，不覆盖测试 preset。
  - 下一局如果不是脚本再次写入，就会恢复正常大厅桥接。

## 判据

- 启动脚本能拉起地图，只说明安装和启动链条通了。
- `login_required` 只说明没有新增启动级阻塞，不代表已经真正进图。
- 真正验证通过仍然要看：
  - 是否进入地图。
  - 开局指挥官单位是否正确。
  - 地图初始化器是否运行。
  - 敌方进攻 / 发展 / 运输 / 护送逻辑是否还在。
