# 单位生产、技能与运行时差异应聚合诊断

## 问题

“建筑造不出单位”“单位造出来没有技能”通常不是单一 XML 字段错误，而是以下链路任一
环节断开：

1. Train/Build/Morph `InfoArray` 没有指向目标 Unit ID。
2. 生产者没有继承或定义对应生产能力。
3. 生产者有能力，但 `CardLayouts` 没有匹配的 `AbilCmd`。
4. Requirement 或 `Restricted` 状态隐藏了命令。
5. 目标单位的能力只存在于父 Unit，或父依赖未加载。
6. Galaxy 在运行时添加、移除或锁定单位/能力。
7. `CatalogFieldValueSet*` 让游戏内数据偏离纯 XML 视图。

过去逐项手查容易遗漏依赖覆盖和运行时层，也会重复消耗时间。

## 修复

`sc2-editor-toolkit diagnose-unit` 现在按有效依赖顺序合并 Catalog，展开 Unit `parent`
继承，并自动检查生产槽、生产者能力、命令卡、预期技能和 Galaxy 运行时事件。

运行时扫描必须同时匹配原生函数名和带前缀包装函数。正则若写成
`[A-Za-z_][A-Za-z0-9_]*TechTreeUnitAllow`，会错误要求函数名前存在额外字符，从而漏掉
精确的 `TechTreeUnitAllow`。可选前缀应写为：

```text
(?:[A-Za-z_][A-Za-z0-9_]*)?TechTreeUnitAllow
```

`TechTreeAbilityAllow` 和 `UnitAbilityAdd/Remove` 使用相同策略，并由回归测试覆盖原生
函数名。

## 原则

- 先确认依赖和 ID 所有权，再改 XML。
- 用继承后的 Unit 视图判断技能和卡牌，不能只看子条目自身。
- 静态 XML 和检测到的运行时状态必须分别输出。
- 依赖不完整默认失败，只有显式接受时才能继续。
- 新漏报必须进入测试或解析规则，不能只记在文档里。
