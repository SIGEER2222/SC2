## 二、评审发现的问题

### 问题 1：RebornMapAdapter 仍硬编码 "RebornKerrigan"（严重）

**位置**：[RebornMapAdapter.galaxy:76](file:///e:/Code/MyMod/SC2/合作指挥官-起义狂潮/Mods/Reborn/RebornMapAdapter.SC2Mod/Base.SC2Data/RebornMapAdapter.galaxy)

```galaxy
void libRebornAdapter_OnAfterPlayersInit () {
    libRebornAdapter_RegisterCommanderSlot(1, "RebornKerrigan");  // ← 硬编码
    PlayerGroupAdd(libRebornAdapter_commanderPlayers, 1);
}
```

**矛盾**：任务 9 目标是去除 MapProfile 中的硬编码 RebornKerrigan，MapProfile 已改为 `commanderId: null + allowRuntimeOverride: true`，但 Adapter 内部仍写死 "RebornKerrigan"。

**影响**：无论启动器选择哪个指挥官，Adapter 都会注册为 RebornKerrigan，导致 defaults.json 的 `defaultCommander: "TerranRaynor"` 失效。

**修复方向**：
- 方案 A：Adapter 从 Bank（CampaignXCore）读取实际选中的指挥官 ID
- 方案 B：启动器通过 `SetMapVariable` 或自定义 Bank 字段注入 commanderId
- 方案 C：在 `launch-reborn-commander.ps1` 中根据 `-Commander` 参数动态改写 galaxy 文件（不推荐，破坏文件不可变原则）

### 问题 2：TerranRaynor.json 字段冗余（中等）

**位置**：[TerranRaynor.json](file:///e:/Code/MyMod/SC2/合作指挥官-起义狂潮/Mods/7vs1/CommanderPackages/TerranRaynor.json)

manifest 同时包含两套字段：
- cli 验证期望：`identity` / `catalog` / `runtime` / `metadata` / `validation`
- schema 期望：`commanderId` / `displayName` / `dataCenter` / `modPath` / `techTree` / `runtimeHooks` / `panelLayout`

**冗余点**：
- `runtime.init/applyTech/createStartSquad` 与 `runtimeHooks.initFunction/applyTechFunction/createStartSquadFunction` 表达完全相同的信息
- `catalog.ownedIds`（49 项）与 `techTree.buildings + units + abilities` 大量重复
- `metadata.modName/dataCenterId` 与 `modPath/dataCenter` 重复

**影响**：维护时需同步两套字段，容易不一致。

**修复方向**：统一 schema 与 cli 验证逻辑，删除其中一套。建议保留 schema 版本（`commanderId`/`techTree`/`runtimeHooks` 等），让 cli 适配 schema。

### 问题 3：defaults.json 与 Adapter 默认值不一致（中等）

**位置**：
- [defaults.json:3](file:///e:/Code/MyMod/SC2/合作指挥官-起义狂潮/Mods/Reborn/MapProfiles/defaults.json)：`"defaultCommander": "TerranRaynor"`
- [RebornMapAdapter.galaxy:76](file:///e:/Code/MyMod/SC2/合作指挥官-起义狂潮/Mods/Reborn/RebornMapAdapter.SC2Mod/Base.SC2Data/RebornMapAdapter.galaxy)：硬编码 `"RebornKerrigan"`

**影响**：启动器三级解析（MapProfile → -Commander 参数 → defaults.json）返回 TerranRaynor，但 Adapter 注册的是 RebornKerrigan，运行时行为不可预测。

### 问题 4：29 张地图仅测试 2 张（中等）

**已测试**：zexpedition03_reborn_port、zchar01_reborn_port（均 exit 0，无 ScriptError）

**未测试**：其余 27 张。migrate-reborn-maps.ps1 只是文件复制，没有适配每张地图的触发器差异。

**风险**：部分地图可能存在与 zexpedition03 早期类似的 ScriptError（如嵌套 include、缺失 lib 初始化等）。

**修复方向**：批量运行 `launch-reborn-commander.ps1 -MapName <每张地图> -Commander TerranRaynor`，收集 ScriptError 日志。

### 问题 5：5-Mod 闭包 MPQ 内部不可验证（低）

**位置**：[reborn-5mod-closure.json](file:///e:/Code/MyMod/SC2/合作指挥官-起义狂潮/Shared/Launcher/reborn-5mod-closure.json)

4 个 MPQ 格式 mod（crys_swarm_assets、sibirens_starhooks_common、sibirens_starhooks_swarmstoryutils、sibirens_sundries_swarm_reborn）无法扫描内部结构，旁挂 DataCenter.json 只声明 `containerType: "mpq"`，`spaces: []` 为空。

**影响**：闭包完整性只能通过运行时验证，无法静态检查 MPQ 内部是否包含声明的 GameData 文件。

**当前状态**：可接受。运行时测试已证明 5-Mod 闭包可正常加载。

### 问题 6：MapProfile schema 未要求 commanderId 字段（低）

**位置**：[MapProfile.schema.json:57](file:///e:/Code/MyMod/SC2/合作指挥官-起义狂潮/scripts/sc2-composer/schema/MapProfile.schema.json)

`commanderSlots.items.required: ["slotIndex", "playerId"]`，未包含 `commanderId`。

**评估**：合理。commanderId 可为 null 表示运行时选择，不 required 是正确设计。但 `allowRuntimeOverride` 也未 required，建议至少在 commanderId 为 null 时要求 allowRuntimeOverride=true。
