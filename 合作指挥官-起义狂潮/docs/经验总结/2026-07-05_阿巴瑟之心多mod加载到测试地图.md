## 最终方案

### 1. 地图结构（基于虫心mod测试地图_unpacked 复制改造）

```
Maps/AbathurHeartTest_unpacked/
├── DocumentHeader                    (二进制，依赖表)
├── DocumentInfo                      (XML，依赖声明)
├── MapScript.galaxy                  (主脚本，按 mod 分块生成单位)
├── ComponentList.SC2components
├── MapInfo, t3*, Objects, ...        (地形/物件/触发器等保留原模板)
└── Base.SC2Data/
    └── LibAbathurHeartCatalog.galaxy (生成的单位目录库)
```

### 2. 单位目录生成（_gen_abathur_heart_catalog.py）

- 用 mpyq 解包 MPQ 格式的 .SC2Mod，读取 `Base.SC2Data/GameData/UnitData.xml`
- 已解包目录直接读取 `Base.SC2Data/GameData/UnitData.xml`
- 过滤规则：
  - 跳过注释掉的 CUnit (`<!--`)
  - 跳过 parent 含 MISSILE 的单位
  - 跳过 id 含 Missile/Weapon/Projectile 的可疑武器
  - 跳过基础种族单位（BASE_RACE_UNITS 集合）
  - 跳过状态变体（Burrowed/Cocoon/Uprooted 等后缀）
- 输出 `LibAbathurHeartCatalog.galaxy`：每个 mod 一段数组，提供 `gf_UnitAt(modIndex, unitIndex)` 和 `gf_ModIndexOf(label)` 两个查询函数

### 3. MapScript.galaxy 按 mod 分块生成

- `gv_activeModIndex = -1` 生成全部 mod（6 列 x N 行网格，每块 21x40）
- `gv_activeModIndex = 0..N` 仅生成指定 mod（地图中央）
- 用 `CatalogEntryIsValid(c_gameCatalogUnit, ...)` 过滤无效单位
- 用 `libNtve_gf_CreateUnitsWithDefaultFacing` 生成（不能用 UnitCreate）

## 踩过的坑（关键经验）

### 坑 1：Alenger 子目录结构必须保留

**现象**：所有 mod 平铺到 `Mods/` 根目录后，游戏卡死无 Alerts.txt。

**原因**：mod 之间的依赖路径硬编码了子目录：
- `6阿巴瑟之心.SC2Mod` 依赖 `file:Mods\Alenger\6阿巴瑟.SC2Mod`
- 所有 Alenger 系列 mod 依赖 `file:Mods\Alenger\通用效果.SC2Mod`

如果平铺到根目录，依赖路径找不到目标 mod。

**解决**：Alenger 子目录的 mod 必须保持 `Mods/Alenger/xxx.SC2Mod` 结构。脚本中用 `RelativePath` 字段区分：
- 顶层 mod → `RelativePath = mod.Name`
- Alenger mod → `RelativePath = "Alenger/" + mod.Name`

### 坑 2：Galaxy 局部变量不能在声明时初始化

**现象**：`Script compile error: 解析函数行出错`，指向 `int lv_count = gv_AH_UnitCounts[lp_modIndex];`

**原因**：Galaxy 语法不允许在函数内用 `int lv_x = value;` 同时声明和赋值（C 风格），必须先声明后赋值。

**错误写法**：
```galaxy
void gf_Foo () {
    int lv_count = gv_AH_UnitCounts[0];   // 编译失败
}
```

**正确写法**：
```galaxy
void gf_Foo () {
    int lv_count;                          // 先声明
    lv_count = gv_AH_UnitCounts[0];        // 后赋值
}
```

**注意**：全局变量可以用 `= ` 初始化（`int gv_activeModIndex = -1;` 没问题），只有函数内的局部变量不行。

### 坑 3：mod 环境下 NativeLib API 可能被覆盖

**现象**：`TriggerDebugOutput`、`PlayerSetPropertyInt`、`c_playerPropMinerals`、`c_playerPropVespene`、`c_playerPropSupplies` 全部编译失败，报"无效的参数列表"或"未定义"。

**原因**：VioletsHoTSReworkMod 等 mod 替换或重定义了 NativeLib 的部分内容，导致这些 API 不可用。

**解决**：参照已验证可用的原模板（虫心mod测试地图_unpacked/MapScript.galaxy），只用以下 API：
- `libNtve_gf_CreateUnitsWithDefaultFacing(count, unitType, c_unitCreateIgnorePlacement, player, point)`
- `CatalogEntryIsValid(c_gameCatalogUnit, unitType)`
- `Point(x, y)`
- `TriggerCreate`、`TriggerAddEventMapInit`

不要用 `TriggerDebugOutput`、`PlayerSetPropertyInt` 等。如果需要调试输出，用全局变量或文件写入代替。

### 坑 4：Clear-GameLogs 必须同时处理文件和目录

**现象**：旧日志残留，被误认为是新进程的，导致错误判断加载状态。

**原因**：GameLogs 下的日志（Alerts.txt、ScriptError.txt、Graphics.txt 等）都是**文件**，不是目录。用 `[System.IO.Directory]::Delete` 只能删目录，无法删文件。

**解决**：
```powershell
Get-ChildItem -LiteralPath $logsRoot -Force | ForEach-Object {
    if ($_.PSIsContainer) {
        [System.IO.Directory]::Delete($_.FullName, $true)
    } else {
        [System.IO.File]::Delete($_.FullName)
    }
}
```

### 坑 5：SC2Switcher vs SC2_x64.exe 直接启动

**现象**：用 `SC2_x64.exe -map "path"` 直接启动时，Alerts.txt 中的 `<Parameters>` 字段有时显示的是其他地图路径（可能是上次启动的残留）。

**原因**：SC2Switcher 会缓存或重定向地图路径。直接用 SC2_x64.exe 在某些环境下行为不一致。

**解决**：用 `SC2Switcher_x64.exe $mapLive` 启动（和 `launch-7vs1-coop-test.ps1` 一样的方式），这是最稳定的方式。

### 坑 6：DocumentHeader 依赖路径分隔符

**现象**：依赖路径混合 `/` 和 `\` 时可能识别失败。

**解决**：SC2 mod 的 DocumentInfo 中依赖路径用反斜杠 `\`（如 `file:Mods\Alenger\6阿巴瑟.SC2Mod`），和 mod 自带的 DocumentInfo 保持一致。脚本中：
```powershell
$depPath = "file:Mods\" + $mod.RelativePath.Replace("/", "\")
```

## 维护建议

1. **新增 mod 时**：放入对应目录（顶层或 Alenger/），重新运行 `_gen_abathur_heart_catalog.py` 生成新的 LibAbathurHeartCatalog.galaxy
2. **mod 依赖路径变化**：用 `_check_mod_deps.py` 检查所有 mod 的 DocumentInfo，确认依赖路径格式
3. **单位过滤规则调整**：修改 `_gen_abathur_heart_catalog.py` 中的 `BASE_RACE_UNITS`、`STATE_VARIANT_SUFFIXES`、`is_suspicious_weapon` 等过滤逻辑
4. **布局调整**：修改 MapScript.galaxy 中的 `gf_SpawnAllMods` 函数的 `lv_cols`、`lv_blockW`、`lv_blockH`、`lv_perRow`、`lv_spacing` 参数
