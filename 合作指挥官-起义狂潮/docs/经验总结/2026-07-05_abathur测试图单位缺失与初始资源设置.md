# Abathur 测试图：单位缺失分析 & 初始资源/人口设置

## 背景
用户反馈 abathur_test_map 测试图存在 3 个问题：
1. 单位不全——畸变体（Aberration）幼虫可变异但展示中缺失，蟑螂变形种不全
2. 利维坦不应该是战役里面的利维坦
3. 地图需大量初始资源 + 500 人口

## 排查结果

### 1. 单位不全：mod 本身的设计，不是测试图问题

#### 畸变体（Aberration）
- **不存在作为独立单位 ID**——mod 的 `UnitData.xml` 中没有 `id="Aberration"` 的 CUnit 定义
- 在 mod 中是 **Zagara 指挥官**的 `InfestedAbomination`（被感染的憎恶兽）的 4 个升级分支之一：
  - AberrationPlaguebearerPurchase（瘟疫使者）
  - AberrationMutagenicFissionPurchase（诱变裂变）
  - AberrationChaosSpawnPurchase（混沌造物）
  - AberrationImposingPresencePurchase（畸变甲幕）
- Larva 的所有 trains 列表（LarvaTrain + LarvaTrainSwarm + LarvaTrainSwarm2）都**没有 Aberration**
- **结论**：Aberration 不是 Abathur 可生产单位，是 Zagara 专属

#### 蟑螂变形种（RoachCorpser / RoachVile）
- mod 中确实存在这两个单位（`UnitData.xml` 行 16959、16973）
- 但只通过 **Naktul 指挥官**的 `NaktulRoachTrain` 能力训练：
  - Train2 → RoachCorpser（腐蚀蟑螂）
  - Train5 → RoachVile（恶性蟑螂）
- Larva 的 trains 列表只有 Train10 → Roach（普通蟑螂）
- Roach 自身的 morphs_to 只有 RoachBurrowed（钻地状态），没有 RoachCorpser/RoachVile
- **结论**：RoachCorpser/RoachVile 是 Naktul 专属，不是 Abathur 的蟑螂变形种

#### Abathur 完整单位列表（已确认完整）
Larva 的 3 个训练能力共 41 个 Train 项（其中 1 个空，实际 40 个）：
- LarvaTrain（17 个）：Drone, Zergling, Overlord, Hydralisk, Mutalisk, Ultralisk, Roach, Infestor, Corruptor, Viper, SwarmHostMP, Baneling, HotSHunter, HotSSplitterlingBig, Scourge, Brutalisk
- LarvaTrainSwarm2（21 个）：Pygalisk, ZerglingToxic, FrostFiend, BileTitan, Igniter, Ravager, HunterKiller, Hydralisk2, MutaliskChar, Mamba, MutaliskAnkylos, Mesmer, BaneHost, VespidHost, UltraliskSavage, UltraliskKaldir, IzshaGuardian, Kraken, (空 Train19), Blightbringer, Omegalisk, Leviathan
- LarvaTrainSwarm（3 个）：DefilerMP, (空 Train10), BroodLord

加上 Drone 的 ZergBuild（13 个 Zerg 建筑）+ Corruptor morphs_to（BroodLord）+ 递归 morphs_to 链（Overseer, Lair, Hive, GreaterSpire）= **59 个 Abathur 单位/建筑**

### 2. 利维坦：mod 自身设计为空壳单位
mod 中 Leviathan 单位定义：
```xml
<CUnit id="Leviathan">
    <EnergyRegenRate value="1"/>
    <CostResource index="Minerals" value="1500"/>
    <CostResource index="Vespene" value="1200"/>
    <Food value="-20"/>
    <FlagArray index="ArmySelect" value="1"/>
    <KillXP value="400"/>
</CUnit>
```
- **attributes 为空，abilities 为空，weapons 为空**
- actor 引用 `Spell_SpawnLeviathan_WarpIn`（spawn 特效）
- 在原版 SC2（alliedcommanders.sc2mod）中也只是占位单位
- 实际游戏逻辑可能由触发器动态注入
- **结论**：是 mod 本身的实现，测试图无法改进

### 3. 地图初始资源 + 500 人口（已修复）

修改 `MapScript.galaxy` 的 `gt_spawn_Func`，在生成单位前设置玩家 1 资源：
```galaxy
// 初始资源：99999 矿物 + 99999 气体 + 500 人口上限
PlayerModifyPropertyInt(1, c_playerPropMinerals, c_playerPropOperSetTo, 99999);
PlayerModifyPropertyInt(1, c_playerPropVespene, c_playerPropOperSetTo, 99999);
PlayerModifyPropertyInt(1, c_playerPropSuppliesLimit, c_playerPropOperSetTo, 500);
```

#### 关键 native 函数
- `PlayerModifyPropertyInt(player, property, operation, value)`
- 属性常量：
  - `c_playerPropMinerals = 0`
  - `c_playerPropVespene = 1`
  - `c_playerPropSuppliesLimit = 6`（注意不是 FoodLimit）
- 操作常量：
  - `c_playerPropOperSetTo = 0`（设置为）
  - `c_playerPropOperAdd = 1`（增加）
  - `c_playerPropOperSubtract = 2`（减少）

## 经验总结

1. **判断单位归属时不能只看玩家直觉**：用户认为"畸变体应该可变异"，但实际 mod 中 Aberration 不是独立单位，是 Zagara 专属的升级分支
2. **多指挥官 mod 中"看似缺失"的单位通常属于其他指挥官**：
   - Aberration → Zagara（InfestedAbomination 的升级）
   - RoachCorpser/RoachVile → Naktul
3. **用 sc2_unit_explorer.py 查询单位的 produced_by 字段**可以快速判断单位归属
4. **Galaxy 设置玩家初始资源用 `PlayerModifyPropertyInt` + `c_playerPropOperSetTo`**，不要找 PlayerSetPropertyInt（不存在）
5. **人口上限常量是 `c_playerPropSuppliesLimit`**（不是 FoodLimit）

## 二次修复（用户反馈后）

### 问题1：人口上限没生效

第一次在 `gt_spawn_Func` 中调用 `PlayerModifyPropertyInt(1, c_playerPropSuppliesLimit, c_playerPropOperSetTo, 500)` 没生效。

**原因**：mod 的 `Lib48DF4533.galaxy` 在游戏初始化时也会调用 `PlayerModifyPropertyInt` 修改人口上限（用 `c_playerPropOperAdd`/`Subtract`），可能在我们的 `SetTo` 之后执行，覆盖了设置。

**修复**：添加独立的延时触发器 `gt_resetResources`，用 `TriggerAddEventTimeElapsed(gt_resetResources, 3.0, c_timeReal)` 在游戏初始化 3 秒后重置资源/人口上限，避开 mod 初始化覆盖。

### 问题2：蟑螂的尸体虫变种和宿主的掘地虫变种缺失

**Abathur 进化分支变种**通过 mod 触发器 `TechTreeUnitAllow(player, "UnitID", true)` 解锁后，用 `libNtve_gf_ReplaceUnit` 把原版 Roach/SwarmHostMP 替换为变种：
- RoachCorpser（腐蚀蟑螂）
- RoachVile（恶性蟑螂）
- SwarmHostSplitA（分裂虫 A，掘地虫变种）
- SwarmHostSplitB（分裂虫 B，深坑道变种）

测试图不模拟进化分支选择，直接生成变种单位本身。需要在生成前 `TechTreeUnitAllow(1, "UnitID", true)` 解锁，否则单位会被 `CatalogEntryIsValid` 跳过（mod 默认锁定）。

### 问题3：可购买科技灰色问题（未解决）

用户反馈：
- 雷兽、宿主、飞龙的可购买科技全是灰色
- 克拉肯和守护者甚至没有可购买科技
- 爆虫的也丢了
- 正常的：刺蛇、跳虫、脊针爬虫、孢子爬虫

**排查结果**：
- 刺蛇的 Purchase 能力（HydraliskCripple 等）和 Abathur 命名空间的 Purchase 能力（AbathurMutaliskExplosiveGlaivePurchase 等）结构相同，都使用 `Requirements="NotXPurchased"`（CountBehavior == 0）
- mod 中没有触发器给单位添加 Abathur Purchase Buff
- mod 中没有 TechTreeAbilityAllow 锁定这些能力

**可能原因**（未验证）：
- Charge 全局共享（CountMax=1）导致只有第一个单位能用
- 或者 mod 的 Requirement 评估逻辑在测试图环境异常

**结论**：可能是 mod 本身的 Charge/Requirement 逻辑问题，需要更深入分析。当前测试图不解决此问题。
