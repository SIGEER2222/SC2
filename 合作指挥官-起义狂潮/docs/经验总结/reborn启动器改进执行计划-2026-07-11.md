# Reborn 启动器改进执行计划

> 日期：2026-07-11
> 关联文档：`reborn启动器工程化总结-2026-07-11.md`、`指挥官地图组合框架设计.md`、`数据中心驱动项目结构设计.md`
> 目标：把当前 Reborn 启动器从“能跑的兼容脚本”推进为可接入 CompositionPlan 和数据中心体系的过渡执行器。
> 原则：短期保留可运行路径，中期收敛事实来源，长期移除全量 Galaxy 注入和 CoreRuntime 全量 include。

## 1. 总体判断

当前 Reborn 启动器工程化工作已经解决了最紧急的问题：

- 地图能启动。
- CoreRuntime 不再被复制进地图 `Base.SC2Data`。
- 依赖重写、mod 同步、map 同步和启动流程被拆成共享模块。
- Reborn 依赖、Alenger 依赖和 CommanderUnits 映射已经从脚本硬编码迁移到 JSON 配置。

但它仍然是一个 compatibility launcher，而不是最终的组合平台：

- 启动器仍在承担依赖规划、Galaxy 注入、地图副本修改和执行器职责。
- `CoreRuntime` 仍编译期硬编码全部指挥官 Runtime 和 Adapter。
- Catalog 数据可以按需加载，但 Galaxy 编译仍要求全量文件存在。
- 当前 JSON 配置还没有接入 `CompositionPlan`，可能成为第二事实来源。
- 成功启动不能证明单位、科技、技能、按钮、顶栏、Bank 和地图任务行为都正确。

因此，本计划把现有实现定位为：

```text
RebornCompatibilityLauncher
  -> 短期止血与验证入口
  -> 中期 CompositionPlan 执行器雏形
  -> 长期被 sc2-composer launch 子命令取代
```

## 2. 成功标准

本计划完成后，应满足：

1. Reborn 启动器所有依赖、注入、重写行为都有机器可读清单。
2. 启动器不再维护独立事实，只消费 CompositionPlan 或 CompositionPlan-like plan。
3. Galaxy 注入从目录扫描改为显式 manifest。
4. 配置错误、缺文件、未知 commander、未知 map、重复依赖必须启动前失败。
5. DocumentHeader 和 DocumentInfo 重写有 roundtrip 校验。
6. `zexpedition03 × Raynor` 至少完成静态验证、启动验证和单位诊断验证。
7. 后续接入新 Reborn 地图时，不需要复制粘贴启动器逻辑。
8. 后续接入新指挥官时，不需要修改 Reborn 启动器核心逻辑。

## 3. 当前问题拆解

### 3.1 CoreRuntime 全量 include

现状：

- `LibE0EAE146.galaxy` include 所有 Commander Runtime。
- `LibE0EAE146_AdapterBootstrap.galaxy` include 所有 Adapter。
- 即使只选择 Raynor，也必须让所有 CommanderUnits 和 Alenger Adapter 的 Galaxy 文件在编译环境中存在。

风险：

- 新增指挥官会触碰 CoreRuntime。
- 缺少未选中指挥官的 Galaxy 文件也会导致当前组合失败。
- 启动器被迫注入全仓库 Galaxy，掩盖真实依赖边界。

改进方向：

- 短期：显式记录这些 compile-time requires。
- 中期：生成只包含当前组合的 bootstrap。
- 长期：PlatformKernel 不再 include 具体指挥官 Runtime。

### 3.2 Galaxy 注入策略不稳定

现状：

- 为满足 CoreRuntime 硬编码 include，启动器把 CommanderUnits 和 Adapter Galaxy 文件注入地图 `Base.SC2Data`。
- 注入数量已经达到 58 个或更多。

风险：

- 目录扫描会把无关、旧版、临时、实验文件带入编译环境。
- 注入路径和依赖路径的真实边界不清楚。
- 成功启动后难以判断到底依赖了哪个文件。

改进方向：

- 建立 `GalaxyManifest.json`。
- 每个 mod 声明 `compileProvides`、`compileRequires`、`runtimeProvides`。
- 启动器只注入 plan 中列出的文件。

### 3.3 配置层可能成为第二事实来源

现状：

- `commander-units-mapping.json` 维护 commander 到 mod 后缀映射。
- `alenger-mods.json` 维护 24 个 Alenger mod。
- `reborn-dependencies.json` 维护 Reborn 依赖和注入规则。

风险：

- 这些配置和 `Shared/Commanders/*.json`、`DataCenter.json`、MapProfile 可能漂移。
- CLI、Web、toolkit、launcher 可能继续计算出不同依赖。

改进方向：

- 短期为 JSON 加 schema。
- 中期让启动器输出 CompositionPlan-like 报告。
- 长期这些 JSON 被 `Shared/Commanders`、`Shared/Maps/profiles`、`DataCenter.json` 替代。

### 3.4 DocumentHeader/DocumentInfo 重写缺少强校验

现状：

- 已识别 DocumentHeader 依赖表格式：`count(uint32) + null-terminated strings`。
- 启动器可以重写 DocumentHeader 和 DocumentInfo。

风险：

- 二进制写错可能导致地图能启动但编辑器无法保存或后续损坏。
- DocumentHeader 和 DocumentInfo 不一致可能造成隐性依赖问题。

改进方向：

- 抽出 parser 和 writer。
- 建立 read -> write -> read roundtrip 测试。
- 每次重写后校验 count、字符串集合、顺序、重复项和 DocumentInfo 一致性。

### 3.5 验证覆盖不足

现状：

- 测试记录主要是 exit code、无 ScriptError、依赖数量、Galaxy 注入数量。

风险：

- 无 ScriptError 不代表兵营能造对单位。
- 不代表造出来的单位有技能。
- 不代表科技升级、顶栏、Bank、任务胜负、剧情触发没有被破坏。

改进方向：

- 建立静态验证、启动器 dry-run、Galaxy checker、单位诊断、进图测试、运行时 probe 分层验证。

## 4. 执行路线

### Phase 0：冻结现有行为基线

2. dry-run 输出当前行为：
   - source map。
   - generated map。
   - selected commander。
   - live mod sync 列表。
   - stale mod 清理列表。
   - dependency rewrite 列表。
   - galaxy inject 列表。
   - DocumentHeader 依赖列表。
   - DocumentInfo 依赖列表。
3. 记录当前 `zexpedition03 × TerranRaynor` 的基线报告。
4. 把基线报告存入 `docs/经验总结/reborn-launcher-baselines/`。

建议产物：

```text
合作指挥官-起义狂潮/docs/经验总结/reborn-launcher-baselines/
```

完成标准：

- 后续改动可以用该报告判断行为是否变化。

### Phase 1：配置 schema 和启动前硬失败

目标：先把配置可靠性补上，防止“能启动但配置错了”的状态继续扩散。

任务：

1. 新增 schema：

```text
合作指挥官-起义狂潮/scripts/sc2-launcher/schema/
  commander-units-mapping.schema.json
  alenger-mods.schema.json
  reborn-dependencies.schema.json
```

2. 为配置加载增加校验：
   - JSON 可解析。
   - schemaVersion 支持。
   - commander id 唯一。
   - mod suffix 唯一。
   - dependency path 非空。
   - live path 和 workspace path 可计算。
   - galaxy inject rule 不允许空匹配。
   - unknown commander 必须失败。
   - unknown map family 必须失败。
   - duplicate dependency 必须失败或显式去重并报告。

3. 添加 launcher config check 命令：

```powershell
pwsh 合作指挥官-起义狂潮/scripts/reborn/launch-reborn-commander.ps1 `
  -Commander TerranRaynor `
  -Map zexpedition03 `
  -CheckOnly
```

4. 检查失败时输出：
   - 失败字段。
   - 配置文件路径。
   - 期望格式。
   - 当前值。
   - 不执行任何 map/mod 写入。

完成标准：

- 配置错误在 map sync 和 mod sync 前失败。
- 不存在参数失败后静默降级。
- CI 或本地检查可以单独跑配置校验。

### Phase 2：显式 GalaxyManifest

目标：移除“扫描目录后注入所有 Galaxy”的隐式行为。

任务：

1. 新增 manifest schema：

```text
合作指挥官-起义狂潮/Shared/Galaxy/galaxy-manifest.schema.json
```

2. 新增 Reborn 过渡 manifest：

```text
合作指挥官-起义狂潮/Shared/Galaxy/reborn-compat-galaxy-manifest.json
```

3. manifest 字段建议：

```json
{
  "schemaVersion": 1,
  "id": "reborn.compat.galaxy",
  "mode": "compatibility-shim",
  "entries": [
    {
      "owner": "Commander.TerranRaynor",
      "sourceMod": "Mods/7vs1/CommanderUnits_Raynor.SC2Mod",
      "compileProvides": ["LibE0EAE146_RaynorRuntime"],
      "compileRequires": [],
      "runtimeProvides": ["RaynorRuntime_Init", "RaynorRuntime_ApplyTech"],
      "files": [
        "Base.SC2Data/LibE0EAE146_RaynorRuntime.galaxy"
      ],
      "reason": "CoreRuntime compatibility include"
    }
  ]
}
```

4. 启动器改造：
   - 不再扫描全目录。
   - 根据 selected commander、CoreRuntime 兼容模式和 Reborn adapter 计算 manifest 子集。
   - 每个注入文件必须来自 manifest。
   - manifest 中没有声明的 Galaxy 文件禁止注入。

5. 报告输出：
   - 注入文件数量。
   - 每个文件 owner。
   - 每个文件 reason。
   - 是否 selected commander 必需。
   - 是否 compatibility-only。

完成标准：

- 注入清单稳定、可 diff。
- 删除目录中的无关 Galaxy 不会改变 plan。
- 新增 Galaxy 文件不会被自动带入。

### Phase 3：DocumentHeader/DocumentInfo roundtrip 工具化

目标：把二进制依赖重写从脚本技巧升级为可测试工具。

任务：

1. 抽出独立模块：

```text
合作指挥官-起义狂潮/scripts/sc2-launcher/document-dependencies.ps1
```

2. 提供函数：
   - `Read-DocumentHeaderDependencies`
   - `Write-DocumentHeaderDependencies`
   - `Read-DocumentInfoDependencies`
   - `Write-DocumentInfoDependencies`
   - `Test-DocumentDependencyRoundtrip`
   - `Compare-DocumentDependencySets`

3. 校验规则：
   - DocumentHeader count 等于字符串数量。
   - 字符串均以 null 终止。
   - 不存在空字符串依赖。
   - 不存在重复依赖。
   - DocumentHeader 与 DocumentInfo 的依赖集合一致。
   - 写入后再读取结果一致。
   - 失败时不启动游戏。

4. 增加 fixture：

```text
合作指挥官-起义狂潮/scripts/sc2-launcher/tests/fixtures/document-dependencies/
  simple.DocumentHeader
  reborn-zexpedition03.DocumentHeader
  simple.DocumentInfo
```

完成标准：

- roundtrip 测试能独立运行。
- 任何依赖重写后都能输出 before/after diff。
- DocumentHeader 写坏时能在启动前失败。

目标：把现有配置和数据中心概念打通，避免 launcher 配置继续成为孤立系统。

   - `RebornBridge.SC2Mod`
   - `RebornMapAdapter.SC2Mod`

2. DataCenter.json 最小字段：

```json

  "schemaVersion": 1,
  "id": "Commander.TerranRaynor",

  "owner": "TerranRaynor",
```

### Phase 6：Raynor 单指挥官完整验证

目标：用 Raynor 打通“配置 -> 依赖 -> 注入 -> 进图 -> 单位行为”的最小闭环。

   - DocumentHeader roundtrip 通过。

2. Galaxy 检查：
   - CoreRuntime checker。
   - RaynorRuntime checker。
   - RebornMapAdapter checker。
   - 生成 bootstrap 或注入后编译环境 checker。

3. 单位诊断：
   - `BarracksRaynor`。
   - `Marine`。
   - `Marauder`。
   - `Vulture`。
   - 至少覆盖生产、按钮、Requirement、TechTree、AbilityCommand。

4. 进图验证：
   - 地图能启动。
   - 玩家 1 是指挥官槽。
   - 地图任务 AI 和胜负没有被替换。
   - 兵营能训练预期单位。
   - 训练出来的单位有预期技能。
   - Raynor 科技升级没有被地图 reset。
   - Reborn 剧情 Bank 不被写入。
   - 无新增 ScriptError。

完成标准：

- 形成 `zexpedition03 × Raynor` 验证报告。
- 报告中每个失败项有 owner：launcher、CoreRuntime、CommanderPackage、MapAdapter、MapProfile、PairPatch。

   - 复制 plan 指定的 map 工作副本。

   - 写入 plan 指定的 DocumentHeader/DocumentInfo 依赖。
   - 启动 SC2。
   - 收集日志和结果。

4. 删除或弃用：
   - 启动器内部 commander 映射。
   - 启动器内部 Alenger 全量列表。
   - 启动器内部 Reborn 依赖硬编码。

完成标准：

- 启动器不再决定“应该加载什么”。

## 5. 任务拆分清单

### 5.1 适合高能力模型/主流程处理

这些任务需要架构判断或可能影响所有权边界，不建议下放给便宜模型：

- CoreRuntime 瘦身策略。
- CompositionPlan schema 决策。
- MapProfile 生命周期 hook 选择。
- CommanderPackage owner 判定。
- Catalog 冲突决策。
- PairPatch 是否成立。
- 运行时 probe 结果解释。
- 进图后单位行为异常的 root cause。
- 是否删除旧 fallback 路径。

### 5.2 适合低成本模型或本地批处理

这些任务高 token、低判断，可拆成本地文件任务包：

1. 批量列出所有 Galaxy include。
2. 批量生成 GalaxyManifest 初稿。
3. 批量检查 JSON 配置字段完整性。
4. 批量列出 mod 物理路径和 live 路径。
5. 批量扫描 `GameData.xml` 和数据空间状态。
6. 批量跑 galaxy-checker 并归类错误码。
7. 批量跑 `diagnose-unit` 并输出矩阵。
8. 批量扫描本地化 key 缺失。
9. 批量扫描 DocumentInfo 依赖。
10. 批量比较 launcher-plan diff。

建议任务包目录：

```text
合作指挥官-起义狂潮/docs/低成本模型任务包/reborn-launcher-improvement/
  01-galaxy-include-inventory.md
  02-galaxy-manifest-draft.md
  03-config-schema-audit.md
  04-document-dependency-fixtures.md
  05-unit-diagnostic-raynor.md
  06-reborn-map-profile-audit.md
```

### 5.3 可直接脚本化的任务

这些任务应优先做成本地脚本，避免重复消耗 token：

- `lint-launcher-config`：校验 launcher JSON。
- `emit-launcher-plan`：输出 CompositionPlan-like report。
- `lint-galaxy-manifest`：校验注入清单。
- `parse-document-header`：解析 DocumentHeader。
- `roundtrip-document-dependencies`：二进制依赖表 roundtrip。
- `diff-launcher-plan`：比较两次 plan 是否稳定。
- `collect-script-errors`：收集 GameLogs ScriptError。
- `summarize-galaxy-checker`：归类 checker 错误码。

## 9. 风险与控制

### 9.1 继续扩大 launcher 职责

风险：

- 启动器变成越来越大的组合编译器。

控制：

- 任何新逻辑先判断是否属于 CompositionPlan。
- 启动器只允许执行 plan，不允许新增组合决策。

### 9.2 Manifest 手工维护漂移

风险：

- GalaxyManifest 与实际文件不一致。

控制：

- 增加 `lint-galaxy-manifest`。
- 增加 include 扫描报告。
- manifest 中每个文件必须有 owner 和 reason。

### 9.3 DocumentHeader 写坏

风险：

- 地图能启动但编辑器保存或后续加载出问题。

控制：

- 重写前备份生成副本。
- roundtrip 必须通过。
- DocumentInfo 和 DocumentHeader 集合必须一致。

### 9.4 验证只看启动成功

风险：

- 单位、技能、科技、UI 和 Bank 问题继续漏掉。

控制：

- 把单位诊断和 runtime probe 纳入验收。
- 每个组合报告区分 `started`、`staticComplete`、`runtimeComplete`。

### 9.5 新旧架构并存太久

风险：

- legacy full include、manifest 注入和 generated bootstrap 三套机制共存。

控制：

- 每个组合明确 `executionMode`。
- 每个 legacy fallback 有移除条件。
- 健康指标统计 legacy 组合数量。

```text

```

目标趋势：

- launcher hardcode 越来越少。
- Galaxy 注入文件数越来越少。
- 未选中指挥官 Galaxy 注入数归零。
- CoreRuntime 具体指挥官 include 归零。
- CompositionPlan 消费入口越来越多。
- PairPatch 数量低于组合数量增长。
