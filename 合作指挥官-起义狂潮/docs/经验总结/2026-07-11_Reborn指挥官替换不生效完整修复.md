# Reborn 指挥官替换不生效 — 完整修复

## 问题现象

Reborn 战役地图（zevolutionbaneling2_reborn_port）启动后，指挥官仍是原版（Raynor），未被替换为 Stetmann。Bank 中 `XMRuntimeDebug` section 缺失，CoreRuntime 初始化链未执行。

## 根因分析（5 层）

### 1. BankList.xml 缺少 CampaignXCore 声明
- **现象**：`BankLoad("CampaignXCore", 1)` 返回 null，无法读取磁盘 Bank 文件
- **根因**：Reborn 地图的 BankList.xml 没有 `<Bank Name="CampaignXCore" Player="1"/>` 声明
- **对比**：所有 31 个 7vs1 地图都有此声明
- **修复**：在 BankList.xml 中添加 `<Bank Name="CampaignXCore" Player="1"/>`

### 2. MapScript.galaxy 缺少 CoreRuntime 初始化调用
- **现象**：`gt_Initialization_Func` 没有调用 `gf_Initialize` 或 `gf_InitializeMapScenario`
- **根因**：Reborn 地图原本是战役地图，没有 7vs1 的 CoreRuntime 初始化逻辑
- **修复**：添加 `include "LibE0EAE146"`、`libE0EAE146_InitLib()` 调用、`gf_InitializeMapScenario("mapId", false)` 初始化调用

### 3. 缺少 LibA070801C include
- **现象**：ScriptError `LibE0EAE146_MutatorRuntime.galaxy (54), 解析函数行出错`
- **根因**：`LibE0EAE146_MutatorRuntime.galaxy` 调用 `libA070801C_gf_EnableDisableMutator`，但 `LibA070801C` 未被引入
- **对比**：7vs1 地图在 MapScript.galaxy 中显式 `include "LibA070801C"` 和 `libA070801C_InitLib()`
- **修复**：在 Reborn 地图的 MapScript.galaxy 中添加相同 include 和 InitLib 调用

### 4. RebornMapAdapter_h.galaxy 数组声明语法错误
- **现象**：ScriptError `RebornMapAdapter_h.galaxy (7), Galaxy数组的定义需要在类型后添加维度`
- **根因**：`string libRebornAdapter_commanderSlot[16];` 语法错误
- **正确语法**：Galaxy 数组声明为 `type[size] varname;`，不是 C/Java 的 `type varname[size];`
- **修复**：改为 `string[16] libRebornAdapter_commanderSlot;`

### 5. Launcher 写入 37 个依赖导致游戏崩溃
- **现象**：依赖列表包含所有 Alenger mods（37 deps），游戏在加载阶段崩溃
- **根因**：`launcher-plan.ps1` 将 `$alenger.dependencyPaths` 加入依赖列表；`launch-reborn-commander.ps1` 同步所有 Alenger mods
- **修复**：移除 Alenger 依赖路径和同步（galaxy 文件仍通过 `Sync-MapRuntimeLibraries` 注入）

## 验证结果

Bank `XMRuntimeDebug` section 确认：
- `Commander` = "Stetmann"
- `TownHallUnit` = "HatcheryStetmann"，`TownHallCount` = 1
- `WorkerUnit` = "DroneStetmann"，`WorkerCount` = 12
- `SecondUnit` = "OverlordStetmann"，`SecondUnitCount` = 1
- `LastPhase` = "InitializeBase.exit"（初始化全部完成）
- 无 ScriptError

## 可复用经验

1. **BankList.xml 是 BankLoad 的前置条件** — SC2 引擎要求 Bank 必须在地图的 BankList.xml 中声明，否则 `BankLoad` 返回 null。从其他地图迁移时务必检查 Bank 声明。

2. **Galaxy 数组语法** — Galaxy 的数组声明是 `type[size] varname;`，与 C/Java 的 `type varname[size];` 不同。这是常见的移植错误。

3. **CoreRuntime 初始化链** — 7vs1 地图的标准初始化模式：
   - `include "LibA070801C"` + `include "LibE0EAE146"`
   - `InitLibs()` 中调用 `libA070801C_InitLib()` + `libE0EAE146_InitLib()`
   - `gt_Initialization_Func` 中调用 `gf_InitializeMapScenario("mapId", false)`

4. **ScriptError 层叠现象** — Galaxy 编译器可能只报告第一个错误。修复一个错误后，后续错误才会显现。需要逐个修复直到完全无 ScriptError。

5. **Bank XMRuntimeDebug 是验证初始化的关键** — 通过检查 `Commander`、`TownHallUnit`、`WorkerUnit`、`SecondUnit` 和 `LastPhase` 可以确认初始化是否成功完成。
