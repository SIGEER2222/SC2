# SC2 不加载自定义命名的 GameData XML 文件

## 问题

### RaynorX 指挥官目录条目找不到

**现象**：进图测试报 ScriptError "无法找到目录条目'BarracksTrainRaynorX'"，对应 `LibE0EAE147_RaynorXRuntime.galaxy` 第 405-409 行的 `CatalogFieldValueCount`/`CatalogFieldValueGet` 调用。

**根因**：SC2 引擎**不会**自动加载 GameData 目录下自定义命名的 XML 文件（如 `AbilData_RaynorX.xml`、`UnitData_RaynorX.xml` 等）。SC2 只加载标准命名的 catalog 文件：
- `AbilData.xml`、`UnitData.xml`、`UpgradeData.xml`、`RequirementData.xml`、`RequirementNodeData.xml` 等

即使 `GameData.xml` 为空（`<Catalog></Catalog>`），也不影响标准文件的自动加载，但非标准命名的文件会被完全忽略。

**验证过程**：
1. 确认文件存在于游戏目录（MD5 一致）
2. 确认 XML 结构正确（ET 解析通过）
3. 确认无 BOM、无编码问题
4. 确认条目定义完整（`BarracksTrainRaynorX` parent=`BarracksTrain`）
5. 将条目合并到主 `AbilData.xml` 后，错误消失

**修复**：将所有 `_RaynorX.xml` 文件中的条目合并到对应的主文件中：
- `AbilData_RaynorX.xml` → `CommanderCatalog/AbilData.xml`
- `UnitData_RaynorX.xml` → `CommanderCatalog/UnitData.xml`
- `UpgradeData_RaynorX.xml` → `CommanderCatalog/UpgradeData.xml`
- `RequirementData_RaynorX.xml` → `CoopZeroPop/RequirementData.xml`（CoopZeroPop 覆盖 CommanderCatalog）
- `RequirementNodeData_RaynorX.xml` → `CoopZeroPop/RequirementNodeData.xml`

### AbilData_RaynorX.xml 重复 ID 问题

**现象**：初次生成的 `AbilData_RaynorX.xml` 包含 52 个条目，其中有大量重复 ID 和非 Raynor 条目（如 `UpgradeToOrbitalSwann`）。

**根因**：正则提取方式不可靠，容易捕获重叠区域和相邻非目标条目。

**修复**：使用 ElementTree 解析获取唯一 ID 列表，序列化后做 `Raynor(?!X)` → `RaynorX` 全局替换。这种方法：
- 保证无重复 ID
- 正确处理 `parent` 属性（含 Raynor 的 parent 也会替换，如 `RaynorTerranAddOns` → `RaynorXTerranAddOns`）
- 不含 Raynor 的 parent 保持不变（如 `BarracksTrain`）

## 关键教训

1. **SC2 只加载标准命名的 catalog XML 文件**。自定义命名文件（如 `AbilData_MyCommander.xml`）不会被加载，即使放在 GameData 目录下。
2. **新增指挥官的 catalog 数据必须合并到主文件中**，不能依赖独立文件。
3. **使用 ElementTree 而非正则提取 XML 条目**，避免重复 ID 和错误捕获。
4. **CoopZeroPop 的 RequirementData.xml / RequirementNodeData.xml 会覆盖 CommanderCatalog 的同名文件**，需求条件必须放在 CoopZeroPop 中。
