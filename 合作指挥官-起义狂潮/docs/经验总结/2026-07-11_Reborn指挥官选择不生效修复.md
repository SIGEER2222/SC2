# Reborn 指挥官选择不生效修复

## 问题

Reborn 战役地图可以进图，但启动器选择的指挥官不生效，仍按默认战役逻辑（凯瑞甘英雄 + 原生基地初始化）加载。

7vs1 地图正常，因使用 `InitializeConfiguredMapScenario` 并在 Init 前从 Bank 读取指挥官。

## 根因（三层）

### 1. 地图内嵌过期 RebornMapAdapter stub

`Maps/zexpedition03_reborn_port.SC2Map/Base.SC2Data/RebornMapAdapter.galaxy` 是早期占位版，`OnAfterUnitsInit` 为空，不调用 `CommanderRuntimeInit`。

SC2 include 优先搜索地图 `Base.SC2Data`，mod 中的完整实现被 shadow。

### 2. MapScript 未调用 adapter 生命周期 hook

`gt_Initialization` 顺序为 Init01→Init02→Init03→…→`Initialize`/`InitializeMapBaseScenario`，从未调用：

- `libRebornAdapter_OnAfterPlayersInit`（读 Bank、注册指挥官）
- `libRebornAdapter_OnAfterUnitsInit`（`CommanderRuntimeInit`）

### 3. Init03 硬编码创建凯瑞甘

`gt_Init03Units` 调用 `libSwaC_gf_CreateHero2(... Kerrigan ...)`，在指挥官叠加层之前已生成战役英雄。

## 修复

### RebornMapAdapter.SC2Mod

- 标准 `_h` / `.galaxy` 分离，避免全局变量重复声明编译错误
- 新增 `libRebornAdapter_ShouldSkipNativeCampaignHero()`（reborn_port 恒为 true）
- `OnAfterUnitsInit`：`Initialize(true)` + `InitializeMapBaseScenario(mapScenarioId)`
- `ShouldSkipNativeCampaignHero`：Bank 指挥官 != Kerrigan 时跳过原生英雄
- 各图 `InitLibs` 调用 `SetMapScenarioId("xxx_reborn")`

### zexpedition03 MapScript

- Init 链插入 adapter hook
- Init03 / IntroSetup / IntroQ 在 overlay 模式下跳过凯瑞甘

### launch-reborn-commander.ps1

- preserve 列表排除 `RebornMapAdapter*.galaxy`
- 每次启动从 mod 复制最新 adapter 到 live 地图

## 验证

```
Commander: TerranRaynor
Map: zexpedition03_reborn_port.SC2Map
exit 0, Alerts.txt 出现, 无 ScriptError, 140.5s
```

## 剩余工作

当前仅 **zexpedition03** 完成 MapScript hook 改造。其余 `*_reborn_port` 地图需按同样模式：

1. 删除内嵌 RebornMapAdapter stub（若有）
2. 在 Init 链插入 adapter hook
3. Init03 跳过原生英雄创建（各图 hero 逻辑不同，需逐图分析）

可抽取 `migrate-reborn-commander-hooks.ps1` 批量处理。

## 可复用经验

1. **MapAdapter 不可只存在于 mod**：地图 `Base.SC2Data` 中的同名 stub 会 shadow mod 实现。
2. **指挥官选择 = Bank 写入 + hook 调用 + 跳过原生 Init**：三者缺一都不生效。
3. **Galaxy 全局数组变量只声明在 `_h.galaxy`**，`.galaxy` 通过 `include *_h` 引用。
