# 弹仓技能 XML 合并污染 + 脚本依赖缺失

## 问题

### 1. 弹仓技能失效（XML 合并污染）

**现象**：RaynorCommandoMarineHangar 弹仓技能不工作，4 个枪兵跟班无法生成。

**根因**：SC2 的 XML 合并机制会将多个 mod 中同名元素的属性**合并**（而非覆盖）。
- `CommanderCatalog.SC2Mod` 的 `AbilData_Raynor.xml` 中 `RaynorCommandoMarineHangar` 使用了
  `Charge Link="Abil/##id##"` 和 `Cooldown Link="Abil/##id##"` —— `##id##` 在 XML 属性中不会被展开，
  是无效引用。
- `CoopZeroPop.SC2Mod` 的 `AbilData.xml` 中有完整正确定义，但 `Charge` 子元素被 CommanderCatalog
  的坏 `Link` 属性污染，导致 Charge 机制失效。

**修复**：
1. 删除 CommanderCatalog.AbilData_Raynor.xml 中 `Charge Link="Abil/##id##"` 和 `Cooldown Link="Abil/##id##"`
2. 将 CommanderCatalog.UnitData_Raynor.xml 中 `NotSelectable` 改为官方标准 `Unselectable`
3. 删除 CoopZeroPop.AbilData.xml 中非标准 `Launch value="ReleaseAtTarget"`（官方弹仓不用）
4. `Leash` 从 8 改为 12（与官方 CarrierHangar/BroodLordHangar 一致）
5. `Time` 从 5 改为 8（与 CarrierHangar 一致），删除 `Distance="1"`

**关键教训**：SC2 多 mod 开发中，同名 catalog 元素的属性会被合并。不能只看最终加载的 mod 定义，
必须检查所有 mod 中同名元素的属性是否冲突。`##id##` 宏只在 galaxy 脚本中展开，XML 属性中不展开。

### 2. quick-compile-check.ps1 缺失函数依赖

**现象**：运行 `quick-compile-check.ps1` 报错 `Convert-TestCommanderToCommanderPowerKey` 和
`Resolve-CommanderPowerPresetPath` 未找到。

**根因**：`campaignxcore-bank.ps1` 调用了定义在 `launch-7vs1-coop-test.ps1` 中的函数，
但 `quick-compile-check.ps1` 没有 dot-source `launch-7vs1-coop-test.ps1`。

**修复**：在 `quick-compile-check.ps1` 的 dot-source 区域后添加两个函数定义（各 4-5 行），
它们只是对 `commander-power-metadata.ps1` 中已有函数的简单包装。
