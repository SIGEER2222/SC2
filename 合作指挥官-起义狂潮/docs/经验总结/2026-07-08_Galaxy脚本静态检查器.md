# Galaxy 脚本静态检查器（galaxy-checker）开发经验

## 日期
2026-07-08

## 背景
用 TypeScript + Chevrotain 实现 Galaxy（SC2 触发器语言）静态检查器，供 AI Agent 写完脚本后自动检查。
位置 `scripts/galaxy-checker`，设计文档与实施计划见 `docs/superpowers/{specs,plans}/2026-07-08-galaxy-checker*`。
最终 106 个 vitest 测试全部通过，对 `CoopZeroPop.SC2Mod/Base.SC2Data`（54 个 Lib*.galaxy）扫描
从初版 17646 个 error 降到 343 个（余下基本为真实问题）。

## 关键实现决策

- **Chevrotain EmbeddedActionsParser 直接产 AST**（不走 CST 转换），单例 parser 复用。
  `skipValidations: !process.env.GALAXY_CHECKER_DEV` 省掉每次启动 ~200ms 的语法自检。
- **native 签名表**：游戏的 `TriggerLibs/natives.galaxy` 不在仓库里，从
  `docs/galaxy/[编辑器全函数]Galaxy Natives Function 5.0.7.txt` 生成 `data/natives.galaxy`
  （2874 个 native），`check()` 默认加载。加载用正则快路径（全量 parse 慢 ~10 倍）。
- **两级符号可见性**：目录模式下 ProjectLoader 收集目录内**全部** .galaxy 的顶层符号
  （lint 范围仍只有 Lib*.galaxy）；单文件模式只看本文件。真实工程务必用目录模式。
- **外部库启发式**：`libXXX_` 引用只有当该前缀在本地符号表中存在时才报
  `XLIB_UNDEFINED_CROSS_REF`；前缀完全未知（libNtve/libLbty 等游戏库）跳过。
  `c_*` 标识符视为游戏常量跳过未声明检查。代价：引用完全不存在的库前缀（如 libE0EAE147 笔误）不报。
- **CLI 用 esbuild 打包**成单文件 `dist/cli.mjs`：未打包时仅 import chevrotain 就要 ~270ms。
  打包后整进程 ~320ms，其中 `check()` 本身对最大文件（LibKMIS.galaxy 451KB）约 130ms（达标 <200ms）。

## 踩坑记录

1. **误报三连**（初版对真实目录 1.7 万 error 的来源）：
   - 注释 token 未从 parser 输入过滤（lexer 保留注释供后用，parse 前必须滤掉）；
   - 真实 `include "x"` **没有分号**（编辑器导出格式），语法里分号要 OPTION；
   - check() 先用 ProjectLoader 收集全局符号、analyze 又重复收集本文件顶层符号 → 每个声明都报
     SEM_DUPLICATE_DECLARATION。目录模式下要静默跳过顶层重复。
2. **Chevrotain 错误恢复会崩溃**：非 native 函数原型（`void foo();`，`_h.galaxy` 头文件全是）
   语法不支持时，错误恢复路径抛 `Cannot read properties of undefined (reading 'tokenTypeIdx')`。
   另外恢复失败时 `parser.program()` 可能返回 `undefined`，下游 `.body` 直接崩。
   两处都要兜底（try/catch + `ast ?? 空 Program`）。
3. **编辑器导出代码的语法形态**要实测才知道：`for ( ; cond ; update)` 空 init、
   `do {} while (...)`、位运算 `|` `&` `^` `<<` `>>`、复合赋值 `|=` `&=`、十六进制字面量、
   数组维度是常量表达式且可多维（`fixed[A+1][B+1] gv_x;`）。写 grammar 前先对真实文件跑一遍收集失配。
4. **BOM 三处都要处理**：check() 主流程、ProjectLoader 符号收集（漏掉会导致整个文件符号丢失，
   连锁产生海量未声明误报）、以及 PROJ_UTF8_BOM 规则本身要在 strip 前用原始字节判断。
5. **类型检查放宽 int→fixed**：Galaxy 隐式提升，`fixed x; x = 1;` 合法，不放宽会有几十个误报。
6. **PowerShell 中文路径**：直接在命令串里写中文路径会因编码丢失匹配不到；用
   working_directory/相对路径或 `-LiteralPath`（路径含 `[]` 时必须）。

## 对 CoopZeroPop 的扫描结论（余下 343 error / 22 warn 的构成）
- `SYNTAX_NO_LOCAL_INIT_ASSIGN` 289：手写库局部变量声明即初始化（项目规则禁止）；
- `SYNTAX_NO_CONTINUE` 18、`XLIB_DISALLOWED_NATIVE` 18（UnitCreate 直调）：项目规则违例；
- `SEM_UNDECLARED_FUNCTION` 11：`SoundPlay`/`SoundPlayAtPoint` 在 5.0.7 native 索引中不存在（疑似已废弃 API，值得人工确认）;
- `XLIB_UNDEFINED_CROSS_REF` 7：`libE0EAE146_tychus_InitVariables` 等本地库确实缺失的符号；
- `XLIB_MISSING_INCLUDE` 22（warning）：include 的 `LibE0EAE146_AbathurRuntime` 等文件在该目录不存在。

这些不是 checker 误报，是地图脚本本身的问题（或项目规则的既有违例），未修改地图脚本。
