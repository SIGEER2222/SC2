## 阶段一：修复"无法打开地图"问题

### 根因

galaxy 文件被复制到地图 Base.SC2Data 后，LibE0EAE146.galaxy 的嵌套 include（Lib67C0F0E7、LibE0EAE146_MutatorRuntime 等）无法解析。7vs1 参考地图 Base.SC2Data 为空，完全通过 mod 依赖链加载。

### 修复内容（launch-reborn-commander.ps1）

1. 移除 galaxy 文件复制到 Base.SC2Data 的策略，改为通过 mod 依赖链加载
2. 添加所有 24 个 Alenger mod 同步到 live 目录
3. 添加运行时依赖重写（Set-MapDependencies），包含 51 个依赖
4. 测试通过：exit code 0，无 ScriptError，游戏正常运行

---

## 阶段二：改为按需依赖 CommanderUnits

参考 `docs/数据中心驱动项目结构设计.md` 的 L4 按需选择理念：

1. **CommanderUnits mod 按需同步和依赖**——只加载选中的指挥官（如 TerranRaynor → CommanderUnits_Raynor），依赖从 51 降到 34
2. **galaxy 文件从工作区注入**——从工作区源目录复制所有 CommanderUnits + Alenger*Adapter 的 galaxy 文件到 Base.SC2Data，满足 CoreRuntime 的 LibE0EAE146.galaxy 硬编码 include 链
3. **不复制 CoreRuntime galaxy 文件**——CoreRuntime 通过 mod 依赖链加载，避免嵌套 include 解析失败
4. **清理 stale mod**——每次启动时清理 live 目录中未选中的 CommanderUnits mod
5. 测试通过：exit code 0，无 ScriptError，58 galaxy 文件注入，34 依赖

### 关键约束

- Alenger mod 必须全依赖（LibE0EAE146_AdapterBootstrap 硬编码 include 所有 LibA*ADAPTER）
- CommanderUnits 的 galaxy 文件必须全部注入（LibE0EAE146.galaxy 硬编码 include 所有指挥官 Runtime），但 Catalog 数据按需加载

## 关键技术发现

### SC2 Galaxy include 搜索路径

- SC2 的 include 指令可以搜索地图 Base.SC2Data 目录和 mod 依赖链
- 7vs1 参考地图不在 Base.SC2Data 放 galaxy 文件，通过 mod 依赖链加载
- 复制 CoreRuntime 的 galaxy 文件到 Base.SC2Data 会导致嵌套 include 无法解析
- 正确做法：只注入 CommanderUnits + Alenger*Adapter 的 galaxy 文件，CoreRuntime 通过 mod 链加载

### CoreRuntime 的硬编码 include

- `LibE0EAE146.galaxy` 硬编码 include 了所有指挥官的 Runtime galaxy 文件（LibE0EAE146_AbathurRuntime、LibE0EAE146_RaynorRuntime 等）
- `LibE0EAE146_AdapterBootstrap.galaxy` 硬编码 include 了 LibA1ADAPTER 到 LibA13ADAPTER
- 这意味着 galaxy 编译需要所有 CommanderUnits 和 Alenger*Adapter 的 galaxy 文件存在
- 但 Catalog 数据（单位、技能、建筑定义）可以按需加载，只加载选中的指挥官 mod

### DocumentHeader 二进制依赖表

- 格式：count(uint32) + 连续的 null 终止字符串
- 前4字节值为依赖数量
- `Set-DocumentHeaderDependencies` 函数可以运行时重写依赖列表
- `Set-DocumentInfoDependencies` 函数同步更新 DocumentInfo XML
