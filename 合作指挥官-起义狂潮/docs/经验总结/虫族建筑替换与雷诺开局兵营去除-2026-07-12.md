# 虫族建筑替换与雷诺开局兵营去除 - 2026-07-12

## 任务内容

用户反馈"应该做替换，而非单纯的清理，不然后面基地的位置就歪了"，要求：
1. 虫族建筑替换而非清理（保留基地位置不偏移）
2. 去掉雷诺开局的三个兵营（BarracksRaynorX, Barracks, BarracksRaynor）

### 问题分析

**原流程**：
1. `OnAfterUnitsInit` 设置 effectiveBaseAnchor = Lair 位置
2. `InitializeBase` 在 Lair 位置创建 CommandCenterRaynor（但 Lair 还在，CC 位置偏移）
3. 2秒后 DeferredCleanup 移除 Lair 和其他虫族单位

**问题**：InitializeBase 创建 CC 时 Lair 还在，导致 CC 位置偏移

### 修复内容

#### 1. RebornMapAdapter.galaxy - DeferredCleanup 改为替换模式
```galaxy
// 旧：RemovePreplacedZergUnits 只移除虫族单位
// 新：ReplacePreplacedZergUnits 在 Lair 原位置重建 CC
void libRebornAdapter_ReplacePreplacedZergUnits () {
    // 第一步：找到 Lair 位置
    // 第二步：移除 InitializeBase 创建的偏移 CC，在 Lair 原位置重建 CC（IgnorePlacement）
    // 第三步：移除所有虫族单位（包括 Lair）
}
```

关键逻辑：
1. 找到 Lair，记录位置 P
2. 移除所有已创建的 CommandCenterRaynor（InitializeBase 创建的，位置偏移）
3. 在 P 位置创建新 CC（c_unitCreateIgnorePlacement 确保位置准确）
4. 移除所有虫族单位（包括 Lair）

### 尝试过的方案

1. **skipTownHallCreate=true + DeferredCleanup 替换 Lair**：
   - 问题：heartbeat 停在 2，Loop_Func 不执行
   - 原因：没有 CC 可能导致游戏进入异常状态
   - 解决：撤销 skipTownHallCreate，让 InitializeBase 正常创建 CC

2. **保留 CC 创建 + DeferredCleanup 位置修正**（最终方案）：
   - InitializeBase 正常创建 CC（位置可能偏移）
   - DeferredCleanup 移除偏移的 CC，在 Lair 原位置重建 CC
   - 验证成功
