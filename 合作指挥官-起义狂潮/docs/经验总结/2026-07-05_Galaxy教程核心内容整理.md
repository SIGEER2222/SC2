## 一．Galaxy 概述

Galaxy 是玻璃渣（Blizzard）出品的游戏 SC2（StarCraftⅡ——星际争霸2）的一种类似 C 的脚本语言。

《星际争霸2》官方第 52 批 FAQ 中对 Galaxy 的描述：

> Q: 星际 2 的地图编辑器还是使用魔兽争霸 3 的 JASS 程式语言吗，还是一种新版本的语言？
>
> A: 星际 2 的地图编辑器使用一种全新的脚本语言，我们把它叫做 Galaxy——银河。这是一种很接近于 C 语言的语言，任何熟悉 C 语言的人对 Galaxy 都可以很快上手。
>
> Q: 它是事件驱动的还是面向对象的？
>
> A: 虽然多数本地函数是基于对游戏对象操作的，但 Galaxy 语言本身不是面向对象的。

Galaxy 是我们在制作 SC2 地图中使用的一种脚本语言，我们使用它来描述如何实现我们需要的效果。Galaxy 可以说是 SE 中功能最强大的部分，它涉及到整个地图制作的方方面面，Galaxy 编写的地图脚本将地图的其他方面，如 Actor、单位数据等串联起来，才构成一张完整的地图。

不过，对比 War3 的地图，SC2 的地图对于脚本支持的需求略小一些。很多内容已经不是必须用脚本来实现，使用 SE 的数据编辑器即可。当然这不是说你可完全脱离 Galaxy 来制作地图。

### 1.1 Galaxy 与 GUI 界面

GUI（Graphical User Interface，图形用户界面）是指采用图形方式显示的计算机操作用户界面。

> 注意：本教程中的 GUI 特指使用数据编辑器的 GUI 界面编写地图脚本。

GUI 与 Galaxy 是互为表里关系，GUI 的本质不过是由触发编辑器自动生成 Galaxy 脚本而已。

查看地图的 Galaxy 脚本方法：在选择任意非库的触发、动作后，按 `Ctrl + F11` 键。

**一张新建地图的原始 Galaxy 脚本示例**：

```galaxy
//=========================================================================
// Generated Map Script
// Name: Just Another StarCraft II Map
// Author: Unknown Author
//=========================================================================
include "TriggerLibs/NativeLib"

// Library Initialization
void InitLibs () {
    libNtve_InitLib();
}

// Trigger Variables
trigger gt_MeleeInitialization;

// Trigger: Melee Initialization
bool gt_MeleeInitialization_Func (bool testConds, bool runActions) {
    // Actions
    if (!runActions) {
        return true;
    }
    MeleeInitResources();
    MeleeInitUnits();
    MeleeInitAI();
    MeleeInitOptions();
    return true;
}

void gt_MeleeInitialization_Init () {
    gt_MeleeInitialization = TriggerCreate(gt_MeleeInitialization_Func);
    TriggerAddEventMapInit(gt_MeleeInitialization);
}

// Trigger Initialization
void InitTriggers () {
    gt_MeleeInitialization_Init();
}

// Map Initialization
void InitMap () {
    InitLibs();
    InitTriggers();
}
```

上述内容就是存储在地图文件根目录下的 `MapScript.galaxy` 文件的内容。

**使用 GUI 和直接写 Galaxy 脚本的差异**：

- 使用 GUI 相对较为安全，出现语法问题的可能性较低；缺点是编写速度较慢，大部分情况下执行效率较直接写 Galaxy 略低。
- 使用 Galaxy 编写地图脚本比较快捷，执行效率高。缺点是很容易出现语法问题，Debug 难度较大，需要一部分英语水平。

> 不同于 WE 下 J（Jass）和 T（Trigger，触发）在制作地图中实现能力上的差别，使用 GUI 完全可以实现 Galaxy 所能实现的内容。

### 1.2 编写 Galaxy 的工具

两种选择：

1. **直接使用 SE 编写 Galaxy**：一般推荐方式
2. **Galaxy++ Editor**：支持类 C 的自定义语法、函数名提示、语法检查及其他功能，并有可见即可得的对话框设计工具

> 注：Galaxy++ Editor 需 .NET 4.0 完整版本支持，使用课件及可得的对话框设计工具还需要 Microsoft XNA Framework Redistributable 3.1 的支持。

## 关键语法要点（基于预览内容 + 错误码翻译总结）

### 与 C 语言的关键差异

Galaxy 虽然类似 C，但有以下重要限制（参见 `2026-07-05_Galaxy错误信息中文翻译.md`）：

| 特性 | C 语言 | Galaxy |
|-----|-------|--------|
| 单行注释 `//` | 支持 | 支持 |
| 块注释 `/* */` | 支持 | **不支持**（`e_unexpectedComment`） |
| `switch` 语句 | 支持 | **不支持**（`e_unexpectedSwitch`） |
| `goto` 语句 | 支持 | **不支持**（`e_unexpectedGoto`） |
| `continue` 语句 | 支持 | **不支持**（`e_unexpectedContinue`） |
| `++` / `--` 操作符 | 支持 | **不支持**（`e_unexpectedOperator`） |
| `signed` / `unsigned` | 支持 | **不支持**（`e_unexpectedSign`，类型隐式有符号） |
| `new` 动态内存分配 | 支持 | **不支持**（`e_unexpectedNew`） |
| 预处理指令 `#include` 等 | 支持 | **不支持**（`e_unexpectedDirective`，使用 `include` 关键字） |
| 隐式类型转换 | 部分支持 | **不允许**（`e_noImplicitCast`） |
| 结构嵌套自身 | 支持 | **不支持**（`e_noNestedStruct`） |
| 结构前置声明 | 支持 | **不支持**（`e_noForwardSupport`） |
| 局部变量位置 | 任意位置 | **必须在函数顶部**（实践中验证） |
| 局部变量初始化 | `int x = 0;` | **不能用 `=` 初始化**，必须先声明再赋值（实践中验证） |

### 触发器函数标准模板

```galaxy
trigger gt_XXX;  // 全局触发器变量

bool gt_XXX_Func (bool testConds, bool runActions) {
    // Actions
    if (!runActions) {
        return true;
    }
    // ... 触发器动作代码 ...
    return true;
}

void gt_XXX_Init () {
    gt_XXX = TriggerCreate(gt_XXX_Func);
    // 注册事件
    TriggerAddEventMapInit(gt_XXX);  // 例如：地图初始化事件
}

// 在 InitTriggers() 中调用 gt_XXX_Init();
```

// exact=true: 精确匹配（无法传参）

### 2. 字符串处理

```galaxy
// Galaxy 没有 StringTrim 函数，需手动循环跳过空格
int lv_i = lv_prefixLen + 1;
while (lv_i <= lv_msgLen) {
    string lv_ch = StringSub(lv_msg, lv_i, lv_i);
    if (lv_ch != " ") {
        break;
    }
    lv_i += 1;  // 注意：不能用 lv_i++
}

// 字符串拼接
string lv_result = "prefix" + IntToString(42);  // OK
// text lv_t = "prefix" + IntToText(42);  // 错误！text 不能与 string 拼接
```

### 3. 玩家颜色设置

```galaxy
// 第三个参数：true = 同步改变已存在单位颜色；false = 只改玩家颜色头衔
PlayerSetColorIndex(1, 5, true);  // 玩家1 设为黄色，并同步改变已存在单位颜色

// 颜色索引参考 SC2 TeamColors:
// 0=白 1=红 2=蓝 3=青 4=紫 5=黄 6=橙 7=绿 8=粉
// 9-15 为扩展颜色
```

### 4. 单位创建

```galaxy
// 直接调用 UnitCreate 会报 "incorrect parameter count" 编译错误
// 必须使用官方包装函数：
libNtve_gf_CreateUnitsAtPoint2(1, "Marine", c_unitCreateIgnorePlacement, 1, lv_point);
```

### 5. 局部变量规则

```galaxy
// 错误：在 if 块内声明局部变量
bool gt_Func (bool testConds, bool runActions) {
    if (true) {
        int lv_x = 0;  // 编译错误！
    }
}

// 正确：局部变量必须声明在函数顶部
bool gt_Func (bool testConds, bool runActions) {
    int lv_x;  // 先声明
    if (!runActions) { return true; }
    lv_x = 0;  // 后赋值（不能用 = 在声明时初始化）
    if (true) {
        lv_x = 1;
    }
}
```

### 6. continue 替代方案

```galaxy
// 错误：Galaxy 不支持 continue
while (lv_i < 100) {
    lv_i += 1;
    if (lv_skip) {
        continue;  // 编译错误！
    }
    // ...
}

// 正确：用 if 块包裹后续逻辑
while (lv_i < 100) {
    lv_i += 1;
    if (!lv_skip) {
        // ... 后续逻辑 ...
    }
}
```
