### 2026-06-08 Raynor 私有单位/建筑模型缺失经验

- 现象：Raynor 私有 opener 切到 `CommandCenterRaynor` / `SCVRaynor` / `MarineRaynor` 后，基地和单位在实机中变成 fallback sphere，模型丢失。
- 关键日志：最新 `Documents\StarCraft II\GameLogs\*-Alerts.txt` 出现 `Scope[CommandCenterRaynor, Unit] Unable to create unit actor. Creating fallback sphere unit.`、`Scope[SCVRaynor, Unit] Unable to create unit actor. Creating fallback sphere unit.`。
- 根因：私有 `CUnit` 已存在，`CActorUnit` 也有 `parent` 和 `unitName`，但继承父 actor 不会自动把父 actor 的 `UnitBirth.<原单位>` 创建事件改成 `UnitBirth.<私有单位>`；因此引擎找不到可响应私有单位出生事件的 actor。
- 第一层修复模式：每个新增私有 `CActorUnit` 都必须显式补出生创建事件，例如：

```xml
<CActorUnit id="SCVRaynor" parent="SCV" unitName="SCVRaynor">
  <On Terms="UnitBirth.SCVRaynor" Send="Create" />
</CActorUnit>
```

- 追加发现：只补 `UnitBirth` 后，已完成的初始基地/SCV/陆战队有模型，但 SCV 新造的建筑在施工阶段仍然无模型。
- 追加日志：`Scope[RefineryRaynor, Unit] Unable to create unit actor. Creating fallback sphere unit.` 后续又出现 `More than one CActorUnit persisting in the same unit scope: ... GenericUnitFallback ... CActorUnit[RefineryRaynor]`；这说明施工开始时没有 actor，完工后 `UnitBirth` 才创建了 Raynor actor。
- 第二层修复模式：所有可建造的私有建筑和挂件还必须显式补施工开始创建事件，例如：

```xml
<CActorUnit id="BarracksRaynor" parent="Barracks" unitName="BarracksRaynor">
  <On Terms="UnitConstruction.BarracksRaynor.Start" Send="Create" />
  <On Terms="UnitBirth.BarracksRaynor" Send="Create" />
</CActorUnit>
```

- 已应用位置：`Mods/7vs1/CommanderCatalog.SC2Mod/Base.SC2Data/GameData/ActorData.xml`，Raynor 私有兵种、基地、飞行建筑、可建造建筑、科技挂件、反应堆均已补 `UnitBirth.<私有单位> -> Create`；可建造建筑和挂件额外补了 `UnitConstruction.<私有建筑>.Start -> Create`。

- 实机反馈：用户手动确认第一层修复后初始单位/基地已有模型，但施工建筑仍缺模型；第二层 `UnitConstruction` 修复已安装到 live，仍需实机确认施工阶段是否不再出现 fallback sphere。

## 继续排查时的优先级

1. 先确认地图能真正进入游戏，而不是只停在前置界面。
2. 再确认地图初始化器是否真的运行：
   - 开局单位/建筑是否正确。
   - 任务 UI 是否出现。
   - 敌方第一轮发展/进攻是否启动。
3. 然后优先测高风险图：
   - 带运输/装载逻辑的图。
   - 带撤离船/救援船逻辑的图。
   - 带护送目标的图。
   - `tzeratul04_7vs1.SC2Map` 这类带 `CustomAI` 的图。
