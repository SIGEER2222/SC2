# 指挥官初始化隔离修复

日期：2026-06-09

## 背景

非雷诺指挥官实测时出现顶部面板、建筑、英雄互相串线，例如德哈卡混到菲尼克斯、斯托科夫、扎加拉、阿塔尼斯、斯台特曼等。该问题优先级高于继续扩大所有地图测试矩阵。

## 根因

启动测试链路之前只把测试指挥官覆盖写入 `CoopZeroPop.SC2Mod` 的 `LibKPVP.galaxy`。但 28 张 `*_7vs1.SC2Map` 都带有地图本地 `Base.SC2Data/LibKPVP.galaxy`，运行时地图本地库会覆盖扩展库。

结果是：

- 原版地图本地 `LibKPVP` 仍按原 Battle.net lobby attribute 或旧逻辑初始化玩家指挥官。
- `CommanderPower` bank 又按测试脚本写入的 commander key 初始化顶部面板/威望/精通。
- 两套来源不一致时，就会出现“顶部技能栏是 A，但基地/英雄/建筑是 B”的混合现象。

## 修复原则

不再用测试脚本整段替换 `LibKPVP_gt_init_Func` 的原版选指挥官循环。那种做法会跳过原版副作用，风险很高。

当前做法只覆盖原版读取指挥官 lobby attribute 的位置：

```galaxy
GameAttributePlayerValue("[bnet:local/0.0/223536]1", lv_player)
```

替换为测试函数：

```galaxy
libKPVP_gf_codex_commander_attribute_for_player(lv_player)
```

这样原版循环仍然负责执行：

- `libKPVP_gf_set_commander_for_player`
- 指挥官等级和经验初始化
- `dehaka/abathur/tychus/mengsk/han` 等特殊玩家组副作用
- `STARTPVP`、英雄、科技、顶部栏后续初始化

## 后续注意

- 不要并行运行多个 `launch-7vs1-coop-test.ps1` 或 smoke，它们会同时写 `E:\SC2\SC2new\StarCraft II\Maps\7vs1` 和 `Mods\7vs1`，可能把 live 目录删到半途中。
- 如果再次出现混合，先检查 live map 本地 `Base.SC2Data/LibKPVP.galaxy` 是否含 `libKPVP_gf_codex_commander_attribute_for_player`，不要只检查扩展 mod。
- `validate-7vs1-commander-init-isolation.ps1` 是本问题的回归测试入口。

## 2026-06-09 追加：Bank 证据与主指挥官写入修复

用户要求禁止调用 Windows 截图功能后，当前实机证据改为 `CampaignXCore.SC2Bank` 的 `XMRuntimeDebug` 运行时记录，不再使用截图、截屏 API、`PrintScreen` 或窗口前台切换。

新增/修复点：

- `launch-7vs1-coop-test.ps1` 写入 `XMRuntimeControl/TestRunId`，`capture-7vs1-ingame-smoke.ps1` 只接受 RunId 匹配的 Bank 证据，避免旧进图结果污染当前测试。
- `launch-7vs1-coop-test.ps1` 新增显式 `Set-CampaignXCorePrimaryCommander`，按 `SelectedCommanders[0]` 写入 `Ach/Commander` 和 `XMRuntimeControl/PrimaryCommander`。
- `Set-CampaignXCoreCommanderPowerPreset` 不再写 `Ach/Commander`。旧实现从哈希表取第一项，顺序不稳定，曾导致 `ZergStetmann` 或 `ZergDehaka` 测试被写回 `Abathur/Raynor`。
- `LibE0EAE146_RuntimeSafety.galaxy` 在存在测试 RunId 与 PrimaryCommander 时，用 `PrimaryCommander` 覆盖旧 `Ach/Commander`，避免原战役存档值污染测试初始化。
- `capture-7vs1-ingame-smoke.ps1` 增加 Bank XML 读取容错，SC2 写 Bank 时短暂空文件或半写入不会让 smoke 脚本崩溃。
- Runtime Bank 证据额外记录 `PrimaryCommander` 与 `AchCommander`，用于区分“启动器写错”和“地图运行时覆盖”。

验证命令：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts\run-7vs1-commander-map-matrix-smoke.ps1 -ReportRoot logs\matrix-smoke-20260609-bank-allmaps-dehaka-primary-bank-fix-v3 -Mode Solo -IncludeCommanders ZergDehaka -WaitSeconds 90 -StopOnFailure
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts\run-7vs1-commander-map-matrix-smoke.ps1 -ReportRoot logs\matrix-smoke-20260609-bank-allmaps-stetmann-primary-bank-fix-v2 -Mode Solo -IncludeCommanders ZergStetmann -WaitSeconds 90 -StopOnFailure
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts\run-7vs1-commander-map-matrix-smoke.ps1 -ReportRoot logs\matrix-smoke-20260609-bank-allmaps-fenix-primary-bank-fix -Mode Solo -IncludeCommanders ProtossFenix -WaitSeconds 90 -StopOnFailure
```

当前实机结果：

- `ZergDehaka`：28/28 地图通过，`MATRIX_FAILED=0`。
- `ZergStetmann`：28/28 地图通过，`MATRIX_FAILED=0`。
- `ProtossFenix`：28/28 地图通过，`MATRIX_FAILED=0`。

静态校验结果：

- `COMMANDER_INIT_ISOLATION_VALIDATE=PASS maps=28`
- `VALIDATION_OK maps=28`
- `PowerShell parse OK`

注意：

- 仍需继续覆盖其余非雷诺指挥官；当前不能据此声明“所有指挥官”完成。
- 如果矩阵中出现一次性 `PrimaryCommander` 与预期不符，先单图复测同一地图/指挥官；可能是旧 SC2 进程或 Bank 写回竞态。复测仍失败时再按真实缺陷处理。
