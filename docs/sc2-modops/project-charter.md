# SC2Mod AI Development Platform Charter

## Purpose

Build an AI-led engineering platform for StarCraft II mod and map development. The platform should let AI agents work from evidence instead of editor intuition by combining structured SC2 asset parsing, RAG, reusable skills, deterministic validators, and multi-agent orchestration.

This project is not a fine-tuned SC2 model as its first goal. It is an agentic RAG and tool-driven development system where models must retrieve facts, call tools, produce reviewable artifacts, and pass validation gates.

## Project Name

Working name: `sc2-modops`.

## Core Principles

- Treat SC2 editor output as source assets that can be parsed, indexed, diffed, and validated.
- Prefer deterministic parsers and validators for facts; use AI for planning, reasoning, synthesis, and review.
- Use cheap or free models for high-volume, low-risk text work.
- Reserve high-intelligence models for architecture, SC2 semantic judgment, graph rules, review, and final conclusions.
- Do not let any model directly declare a high-risk SC2 fix complete without evidence and validation.
- Every repeatable failure should become either a validator, a knowledge card, or a skill rule.

## In Scope

- SC2Mod and SC2Map unpacked asset ingestion.
- Catalog XML graph extraction.
- Galaxy include/function/trigger/runtime indexing.
- RAG over official references, project documents, historical fixes, and handoff notes.
- Skill packages for common SC2 development workflows.
- Multi-agent task routing and handoff formats.
- Validator suite and quality gates.
- Patch proposal, review, validation, report, and archive workflow.
- Future model evaluation and fine-tuning readiness.

## Out of Scope For MVP

- Full visual SC2 Editor automation.
- Fully automatic main-branch merges.
- Training a custom model as the primary knowledge layer.
- Replacing in-game or editor round-trip verification for behavior that static checks cannot prove.
- Large UI platform before the fact layer and validation layer are stable.

## Architecture

```text
Source Layer
  SC2Map / SC2Mod / XML / Galaxy / DocumentHeader / docs / logs

Fact Layer
  Catalog graph / Galaxy index / dependency index / diff inventory

Knowledge Layer
  RAG vector store / knowledge cards / historical incident records

Skill Layer
  Task-specific AI workflows and guardrails

Agent Layer
  Planner / Collector / Analyst / Implementer / Reviewer / Validator / Archivist

Quality Layer
  deterministic validators / evals / review gates / release checks
```

## MVP Deliverables

1. Source inventory generator.
2. Documentation and history chunking pipeline.
3. Catalog graph schema and extractor prototype.
4. Galaxy indexer prototype.
5. Local RAG ingestion format.
6. Initial SC2 skills:
   - `sc2-catalog-closure`
   - `sc2-commander-audit`
   - `sc2-map-dependency`
   - `sc2-galaxy-runtime`
   - `sc2-validator-author`
7. Validator coverage matrix.
8. Model routing and task protocol documents.
9. Cheap-model work queue.

## Quality Gates

- Catalog changes must include a traceable reference chain.
- Galaxy runtime changes must identify the initialization or event entry point.
- DocumentHeader changes must state dependency impact.
- Official-mechanic replication must separate official evidence, project adaptation, and AI inference.
- High-risk patches require strong-model review.
- Validation failures block completion.
- Knowledge generated by cheap models is draft until reviewed.

## Success Criteria

- AI can answer SC2Mod implementation questions with source-backed evidence.
- Common SC2 tasks can be routed to specialized skills.
- Large text ingestion can be delegated to cheap models safely.
- High-risk decisions are reviewed by stronger models.
- At least one existing SC2 bug pattern can be converted into a repeatable validator.
- The system produces reusable reports and knowledge cards after nontrivial tasks.
